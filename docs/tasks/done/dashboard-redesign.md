# 대시보드 리디자인 구현지시서

참고 시안(PM Workspace 스타일 대시보드)의 **레이아웃과 디자인 언어**를 `/dashboard` 요약 탭에 적용한다.
시안의 카드 목록을 베끼는 것이 아니라, **정보 위계 · 그리드 · 카드 문법 · 밀도 · 타이포**를 가져와
지금 우리가 이미 갖고 있는 데이터를 다시 배치하는 작업이다.

- 데이터 추가는 이 작업의 목적이 아니다. 필요한 최소한만 Phase B 로 뒤에 붙였다(부록 A).
- 대상은 **요약 탭뿐**이다. 진척 탭(가중치 · 체크포인트 · 기준선 · 스냅샷 입력)은 그대로 둔다.

## 1. 시안에서 가져올 디자인 언어

| # | 요소 | 규칙 |
|---|---|---|
| 1 | **면 분리** | 페이지 바탕은 옅은 회색, 카드는 흰색. 지금은 둘 다 `#fff` 라 카드가 떠 보이지 않는다 |
| 2 | **카드** | 라운드 16px, 패딩 20px, 카드 간격 16px, 그림자는 아주 약하게(`--elevation-1`) |
| 3 | **카드 머리말** | `제목(굵게) + 부제(작고 흐리게 한 줄) + 우상단 액션(상세보기 ›)`. **세 요소가 항상 같은 자리** |
| 4 | **KPI 스트립** | 최상단 한 줄. `파스텔 아이콘 원 + 라벨 + 큰 숫자 + 보조 한 줄`. 다섯 장 |
| 5 | **비대칭 2열** | 본문은 `7 : 5`. 넓은 쪽에 시간축·목록, 좁은 쪽에 요약·분포 |
| 6 | **숫자 우선 위계** | 숫자는 크게(1.9rem/700), 설명은 작고 흐리게(0.78rem/`--text-faint`). 지금은 둘이 거의 같은 크기다 |
| 7 | **막대 리스트** | 항목 + 가로 막대 + 우측에 `%` 와 `n / m`. 표보다 훑기 쉽다 |
| 8 | **칩** | 상태 · 우선순위 · 등급은 옅은 배경 + 진한 글자의 알약. 지금의 평문 텍스트를 대체 |
| 9 | **여백** | 시안의 인상은 대부분 여백에서 온다. 행 높이 · 카드 패딩을 지금보다 눈에 띄게 키운다 |
| 10 | **탈출구** | 카드마다 "더 보려면 어디로" 링크가 하나씩. 이건 이미 하고 있으므로 **위치만 규격화** |

가져오지 않는 것: 좌측 사이드바(5절), 사용자 아바타 · 알림 벨 · 전역 검색(로그인 · 알림 · 검색이 없다),
기간 선택기(대시보드는 "한 요청, 한 기준일"이다).

### KPI 다섯 장의 출처 (전부 기존 필드)

| 카드 | 값 | 보조줄 | 아이콘 톤 |
|---|---|---|---|
| 전체 진척 | `progress.actualPercent` + 막대 | `PROGRESS_BASIS_LABELS[basis]` | green |
| 계획 대비 | `progress.variancePoints` | `기준선 v{n} 범위` / 없으면 "미산정" | 값에 따라 green·red |
| 지연 업무 | `schedule.delayedCount` | `지연 위험 {atRiskCount}` | red |
| 인수 대기 | `workPackages.acceptancePendingCount` | `실행은 끝났고 승인이 남음` | amber |
| 스프린트 속도 | 마지막 종료 Sprint `donePoints` | Sprint 이름 | violet |

- **`null` 이면 큰 숫자 자리에 "산정 전"** 을 쓰고 막대를 그리지 않는다. 0% 로 대신하지 않는다.
- **편차는 부호를 두고 색으로 방향을 알린다** — 앞섬은 `--success`, 뒤짐은 `--danger`.
  숫자를 절댓값으로 바꾸거나 화살표로 대체하지 않는다(부호가 사라지면 정확한 양을 잃는다).
- **"지난주 대비" 증감은 넣지 않는다.** 과거 값이 남아 있는 지표가 사실상 없어서, 넣으면
  다섯 칸 중 서넛이 거짓이 된다. 필요해지면 부록 A-4.

## 3. 디자인 토큰과 공통 컴포넌트

### 3-a. 토큰 (`frontend/src/style.css`)

**모든 토큰은 라이트 · 다크 쌍으로 정의한다.** 시안이 라이트 전용이라 여기서 가장 실수가 나기 쉽다.
컴포넌트 스코프에 헥사값을 하나라도 남기면 그 자리만 라이트로 남는다.

```
--dash-bg        페이지 바탕 (라이트: 카드보다 한 단계 어두운 회색 / 다크: 카드보다 한 단계 어둡게)
--card-radius    16px
--card-pad       20px
--card-gap       16px
--tint-green/blue/violet/amber/red/gray  + 각 -fg   KPI 아이콘 원
```

- **다크에서는 그림자가 보이지 않는다.** `--elevation-1` 대신 `--border` 1px 로 카드를 세운다.
  토큰 하나(`--card-outline`)를 두고 라이트에서는 `transparent`, 다크에서는 테두리색으로 둔다.
- **파스텔 6종은 새 팔레트가 아니라 기존 `--status-*` · `--accent` 에서 파생시킨다.**
  팔레트를 따로 들이면 다크 모드를 두 벌 관리하게 된다.
- 칩은 이미 있는 `--badge-*` / `--warn-badge-*` 를 재사용한다.
- 숫자에 `font-variant-numeric: tabular-nums` 를 건다(전역 유틸 `.num`).
  자릿수가 바뀔 때 숫자가 좌우로 흔들리는 것을 막는다.

### 3-b. 페이지 바탕색 결정

지금 `--bg` 와 `--surface` 가 둘 다 `#fff` 라, 카드를 아무리 예쁘게 만들어도 배경에서 떠오르지 않는다.

- **먼저 대시보드 안에서만** `--dash-bg` 를 깐다(`.dashboard { background: var(--dash-bg) }`).
  다른 화면은 그대로라 되돌리기 쉽다.
- 반응이 좋으면 **그때 전역으로** `--bg` 를 회색으로 내리고 표 · 폼 · 패널을 `--surface` 로 올린다.
  이건 전 화면에 영향이 가므로 **대시보드 작업에 끼워 넣지 않는다.**

### 3-c. 컴포넌트 (`frontend/src/features/dashboard/`)

| 파일 | 역할 |
|---|---|
| `DashCard.vue` | 카드 크롬 전부. `title` · `subtitle` · `#action` 슬롯 · 기본 슬롯. **크롬은 여기만 갖는다** |
| `KpiCard.vue` | 아이콘 원 + 라벨 + 큰 숫자 + 보조줄 + (선택) 막대. `null` 처리를 여기 한 곳에서 |
| `MiniBar.vue` | 막대 하나. `percent === null` 이면 트랙만 그리고 "산정 전" |
| `BarList.vue` | 막대 리스트 (라벨 + 막대 + 우측 값). 실행 방식 분포 · 단계별 진척이 같이 쓴다 |
| `StatChip.vue` | 상태 · 등급 알약 |
| `icons.ts` | 인라인 SVG 6~8개, `fill="currentColor"` |

- **아이콘은 이모지가 아니라 인라인 SVG** 로 둔다. 이모지는 OS 마다 모양 · 크기 · 색이 달라
  다섯 장의 원 안에서 정렬이 어긋난다.
- `DashboardView.vue` 는 **배치와 탭만** 남긴다 (현재 865줄 → 200줄 이하가 목표).
  지금은 카드 아홉 장의 마크업 · 스타일이 한 파일에 다 들어 있어 그리드를 바꿀 수가 없다.

### 3-d. 반응형

| 폭 | 본문 | KPI |
|---|---|---|
| ≥ 1400px | 7 : 5 | 5장 한 줄 |
| 1100 ~ 1400 | 6 : 6 | 3장 + 2장 |
| 760 ~ 1100 | 1열 | 2장씩 |
| < 760 | 1열 | 1장씩 |

- 12열 그리드 + `minmax(0, 1fr)`. `minmax` 를 빼면 긴 업무명이 열을 밀어 가로 스크롤이 생긴다.
- `.app` 의 1600px 상한은 유지한다.
- 표와 차트는 각자 `.table-scroll` 안에 둔다 — **페이지 본문에는 가로 스크롤이 생기면 안 된다.**

## 4. 지켜야 할 기존 규칙

리디자인은 화면 문제다. 아래를 어기면 대시보드가 "네 번째 의견"이 된다.

1. **`DashboardService` 는 계산하지 않는다.** 배치만 한다. 새 숫자가 필요하면 그 값을 소유한
   도메인 서비스에서 받는다.
2. **산정 전(`null`)은 0% 가 아니다.** 큰 숫자도 막대도 `null` 이면 "산정 전"이다.
3. **한 요청, 한 기준일.** 카드가 늘어도 `GET /dashboard` 한 번. 카드마다 부르면 카드마다 "오늘"이 달라진다.
4. **읽기 전용.** 요약 탭에 변경 API 를 붙이지 않는다.
5. **요약 / 진척 2탭을 유지한다.** 시안에 탭이 없다고 없애면 숫자의 근거를 입력할 곳이 사라진다.
6. **캐시 키는 그대로** (`dashboardCacheKeyFor`).
7. **`record` 에 bean 모양의 `isX()` 금지** — Jackson 이 프로퍼티로 읽어 응답에 필드가 샌다.

## 5. 좌측 사이드바는 별건이다

시안에서 가장 눈에 띄는 구조지만 **대시보드만의 문제가 아니다.**

- 옮기면 **모든 화면의 본문 폭이 ~230px 줄어든다.** 이 앱의 주 내용은 표와 간트라
  `.app` 1600px 상한과 `.table-scroll` 기준이 같이 흔들린다.
- 설계서 §2.2 의 최상위 일곱 개와 Agile 하위 줄이 지금의 상단 nav 구조에 맞춰져 있다.
- 하려면 별도 건으로: ① 접기(아이콘만) 상태를 `localStorage` 에, ② `.app` 상한 재조정,
  ③ 좁은 폭에서 오버레이 전환.
- **이 작업은 상단 nav 를 그대로 두고 본문만 바꾼다.** 순서를 뒤집지 말 것 — 내용이 먼저 들어차야
  폭이 얼마나 필요한지 알 수 있다.

## 6. 단계

### Phase A — 레이아웃과 디자인 언어 (백엔드 변경 0)

1. 토큰 추가(3-a), 대시보드 바탕색(3-b)
2. `DashCard` · `KpiCard` · `MiniBar` · `BarList` · `StatChip` · `icons.ts` 신설
3. `DashboardView.vue` 를 2절 배치로 재구성, 카드 마크업을 컴포넌트로 이관
4. 반응형 4구간(3-d), 다크 모드 확인

**이 단계만으로 화면 인상이 바뀐다. 숫자는 하나도 달라지지 않는다** — 그게 검증 방법이기도 하다
(리디자인 전후 값 비교).

### Phase B — 시안의 시각 요소 중 데이터가 필요한 것 (선택, 부록 A)

Phase A 가 끝난 뒤 하나씩. 각각 독립적이라 순서를 바꿔도 되고 일부만 해도 된다.

## 부록 A. 나중에 붙일 수 있는 것

우선순위 순. **전부 선택이고, Phase A 와 독립이다.**

**A-1. WBS 단계별 진행률 막대 리스트** (시안 좌중단 — 시각적으로 가장 인상이 큰 블록)
`DashboardResponse` 에 최상위 노드별 `PhaseProgress(wbsItemId, code, name, startDate, endDate,
percent, basis, leafTotal, leafDone, incomplete)` 를 싣는다. `WbsTreeAssembler` · `ProgressService` 가
이미 계산한 Summary 롤업을 **그대로** 쓰고 여기서 다시 평균 내지 않는다.
`BarList` 를 그대로 재사용하므로 프론트 작업은 거의 없다.

**A-2. 주요 일정 미니 간트** — A-1 의 날짜를 쓰면 새 조회가 필요 없다.
**마일스톤 엔티티가 이 코드베이스에 없으므로** 이름은 "주요 마일스톤"이 아니라 **"주요 일정"** 이고,
막대 채움은 항목별 색이 아니라 기존 `--status-*`(지연 판정)를 쓴다 — 간트 화면과 뜻이 달라지면 안 된다.

**A-3. 리스크 도넛** — `RaidAssessor` 는 **3등급(높음 6↑ / 보통 3~4 / 낮음) + 미산정**이다.
시안이 4등급이라고 등급을 늘리지 말 것(확률 · 영향이 1 · 2 · 3 가중치라 경계를 더 그을 근거가 없다).
**미산정을 숨기지 않는다.** 조각 색은 종류 색(`--raid-*`)이 아니라 노출도 색을 쓴다.

**A-4. KPI 증감(전주 대비)** — 지금은 과거 값이 남는 지표가 사실상 없다.
`progress_snapshots.metrics` 에 진행률 계열만 있고 지연 건수 · RAID 건수는 없다.
제대로 하려면 `project_weekly_metrics(project_id, week_of, …)` + `UNIQUE(project_id, week_of)` 를 두고
**조회 시 이번 주 행이 없으면 채우는(lazy)** 방식이 맞다(스케줄러를 두면 데스크톱 설치본에서
앱이 꺼져 있는 주에 구멍이 생긴다). **없는 증감을 `0` 이나 `-` 로 채우지 말 것** — "변화 없음"과
"모른다"는 다른 사실이다.

**A-5. 번다운 차트** — `backlog_items.done_at` 으로 재구성할 수는 있지만, 재오픈하면 `done_at` 이 비어
**과거 곡선이 소급해서 바뀐다.** 그리는 경우 카드에 "재구성한 값"이라고 적고, 정확도가 필요해지면
`sprint_daily_snapshots` 를 먼저 둔다.

**A-6. 팀 작업량** — `project_members` × `backlog_items.assignee_member_id`(FK 있음).
**담당자 미지정 항목을 버리지 말고 "미지정" 행으로 마지막에 둔다.** 아바타 사진 컬럼이 없으므로
이름 첫 글자 이니셜 원으로 대체하고, 색은 **이름 해시로 고정**한다(랜덤이면 다시 그릴 때마다 바뀐다).

**A-7. 최근 변경** — `change_logs`(V18) 에 데이터는 쌓이는데 **읽기 API 가 없다.**
`GET /api/projects/{id}/changes?limit=&cursor=` 를 만들면 요구사항 **8.2(진행률 변경 이력 화면)** 의
선행 작업이 된다. 시안의 담당자 · 우선순위 열은 WBS 에 없는 개념이라
`시각 / 대상 / 무엇이 / 이전 → 이후 / 사유` 로 바꾼다.

**새 도메인 예외를 만들면 `GlobalExceptionHandler` 에 함께 등록한다** — Step 4 에서 빠뜨려
Sprint 의 모든 거부가 500 으로 나갔고 서비스 단위 테스트로는 드러나지 않았다.

## 부록 B. 함정

1. **`null` 진척을 `?? 0` 으로 렌더** — 새 컴포넌트마다 반복될 실수. `MiniBar` / `KpiCard` 가
   한 곳에서 처리하고, 카드가 직접 `?? 0` 을 쓰지 못하게 한다.
2. **시안 스크린샷의 헥사값을 그대로 옮기는 것** — 전부 토큰으로. 다크 값을 짝으로 정의.
3. **다크에서 그림자로 카드를 세우려는 것** — 안 보인다. 테두리로 바꾼다(3-a).
4. **컴포넌트에서 토큰 재정의** — 과거 `GanttChart` 의 `--status-completed: var(--status-completed)`
   자기참조로 SVG 가 전부 검게 나왔다.
5. **SVG 차트에 `<title>` 툴팁** — 커스텀 툴팁과 이중으로 뜬다. 간트에서 이미 제거했다.
6. **카드마다 API 호출** — 차트가 생기면 "이 카드만 다시 읽자"가 자연스러워 보인다. 기준일이 갈라진다.
7. **`minmax(0, 1fr)` 누락** — 긴 업무명 하나가 열을 밀어 페이지에 가로 스크롤이 생긴다.
8. **0 분모** — 도넛 · 막대에서 전체가 0건이면 `NaN` 경로가 생긴다. 빈 상태 문구를 먼저 쓰고 그리지 않는다.
