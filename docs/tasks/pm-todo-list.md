# PM TODO 목록 (pm-todo-list)

대상 체크아웃: `D:\Git\ScheduleMgr` (main `40be95b`). 아래 줄번호는 모두 이 커밋 기준입니다.

## 1. 해결할 문제

PM이 프로젝트를 굴리며 생기는 잡무를 적어 둘 곳이 없습니다. "고객 회의 준비", "계약서 검토",
"주간 보고 제출" 같은 일은 산출물이 아니어서 WBS에 넣을 수 없고, 팀의 실행 항목도 아니어서
Backlog에도 맞지 않습니다. 위험·이슈가 아니니 RAID에도 들어가지 않습니다.

| 계층 | 지금 상태 |
|---|---|
| DB | 할 일을 담는 테이블이 없음. 가장 가까운 `raid_items`(V6)는 네 종류(R/A/I/D)로 고정 |
| 백엔드 API | 없음 |
| 화면 | 없음. 최근에 붙은 "Action Item"(V24)은 WBS 항목에 외부 URL을 하나 다는 칸일 뿐, 목록이 아님 |
| 내보내기·커밋 | 해당 없음 |

## 2. 결정된 방향 (사용자와 확정)

| 항목 | 결정 |
|---|---|
| 화면 위치 | **상단 메뉴에 `TODO`를 새로 추가**, 라우트 `/todo`. 순서는 `… RAID \| TODO \| Dashboard` |
| 범위 | **프로젝트별**. 다른 화면처럼 `selectedProjectId`를 따라감 |
| 연결 | **WBS·Backlog·RAID와 연결하지 않음** |
| 필드 | 제목·완료(기본) + **기한·우선순위·담당자(구성원)·메모** |

### 설계서와 부딪히는 점 — 덮어쓰지 말고 기록할 것

설계서 §2.2([`설계서/agile_design/WBS_Agile_Hybrid_PM_Design.md:38-57`](../../설계서/agile_design/WBS_Agile_Hybrid_PM_Design.md))는
메뉴를 `프로젝트 | WBS | Agile | 간트 차트 | RACI | RAID | Dashboard` 일곱 개로 정했습니다.
CLAUDE.md "화면 구조" 절도 진척과 부하를 Dashboard 탭으로 넣은 이유가 "최상위 메뉴를 일곱 개로
유지하기 위해서"라고 적고 있습니다. 이번 결정은 **사용자가 알고 고른 이탈**입니다. 그래서
CLAUDE.md와 설계서 결과 문서에 "8번째 메뉴, 사용자 결정"이라고 사실대로 적습니다(3-5).
Dashboard 탭 안으로 옮기는 것은 이번 범위가 아닙니다.

### 세부 결정 (플래너가 정함, 이유 한 줄씩)

- **완료는 `completed_at TIMESTAMP NULL` 하나로만 표현합니다.** 완료 여부는 이 값이 있는지로
  판단합니다(`completed = completedAt != null`). `done` 불리언을 따로 두면 두 값이 어긋날 수 있습니다.
- **완료 토글은 별도 엔드포인트로 받습니다** — `PUT /todos/{id}/completion`, 본문 `{"completed": true}`.
  Backlog 보관(`/archive`)과 같은 모양입니다. 행의 체크박스가 일반 `PUT`을 부르면 체크박스가 모르는
  필드(메모·기한 등)가 `null`로 덮일 수 있습니다. 커밋 `da96ebe`·진척 basis 엔드포인트와 같은
  종류의 사고이므로 좁은 경로를 둡니다.
- **완료 체크박스는 행에서 바로 저장하고, 확인 창은 띄우지 않습니다.** 다시 체크하면 되돌릴 수
  있기 때문입니다. 추가·수정은 `ModalDialog`에서 합니다(CLAUDE.md "화면 레이아웃 규칙").
  **삭제는 `confirm()`을 거칩니다.**
- **우선순위는 `HIGH`/`MEDIUM`/`LOW`이고 NOT NULL입니다.** 폼의 기본값은 `MEDIUM`(보통)입니다.
  RAID의 확률·영향처럼 "미지정"을 따로 둘 이유가 없습니다. 할 일에는 언제나 상대적인 급함이 있습니다.
- **기한 초과는 RAID와 같은 규칙입니다**([`RaidAssessor.java:48`](../../backend/src/main/java/com/projectflow/domain/RaidAssessor.java)).
  - 기준일은 서버가 정해 `referenceDate`로 응답에 함께 보냅니다.
  - **기한 당일은 아직 초과가 아닙니다.**
  - **완료된 항목은 기한이 지났어도 초과가 아닙니다.**
  - 판정 함수는 `TodoAssessor`라는 순수 도메인 클래스로 따로 두고, `RaidAssessor`를 고치지 않습니다.
- **담당자는 `project_members`를 가리키고 `ON DELETE SET NULL`입니다.** 구성원을 지우면 TODO는
  남고 담당자 칸만 비워져야 합니다. RAID 소유자와 같은 이유입니다(CASCADE면 기록이 사라집니다).
  다른 프로젝트의 구성원을 지정하면 400으로 거부합니다.
- **모든 변경 API는 `{ referenceDate, items }` 전체를 돌려줍니다.** RAID와 같은 이유입니다 — 기한
  초과가 서버 기준일로 판정되므로 클라이언트가 행을 병합하지 않게 합니다.
- **필터·정렬은 클라이언트의 순수 함수로 처리합니다**(`todoFilter.ts`, `raidFilter.ts`와 같은 방식).
  - 기본 정렬은 **미완료 → 우선순위(높음 → 낮음) → 기한(빠른 순, 없는 항목은 뒤) → id**입니다.
    마지막을 id로 두어 편집 중에 행이 튀지 않게 합니다.
  - **완료 항목은 기본으로 숨기고** `완료 포함` 토글로 보여 줍니다.
  - 그 밖의 필터는 담당자·우선순위·`기한 초과만` 세 가지입니다.
- **상단 배너("기한 초과 N건")는 필터와 상관없이 전체를 셉니다.** RAID 배너와 같은 규칙입니다.
- **내보내기·커밋에 포함합니다.** 빠지면 내보내기·복원할 때 TODO만 사라집니다.

### 하지 않기로 한 것

| 안 하는 것 | 이유 |
|---|---|
| WBS·Backlog·RAID 연결 | 사용자 결정. 나중에 붙인다면 `raid_links` 패턴(대상 종류 + id, 삭제 시 분리)을 따름 |
| 여러 프로젝트를 모은 개인 TODO | 사용자 결정. 로그인이 없고, 내보내기·커밋 단위와 맞지 않음 |
| 드래그 재정렬·수동 순서 칸(`position`) | 정렬은 규칙으로 정함. 게다가 드래그 전용 조작은 이미 접근성 부채로 남아 있음(CLAUDE.md 4단계) |
| 상태 여러 단계(진행 중 등) | 할 일 목록은 끝냈는지만 보면 됨. 단계가 필요하면 Backlog를 써야 함 |
| 화면별 CSV 내보내기 | 후속 후보 |

### 3-1. 백엔드 — 도메인·영속성

**새 파일 `backend/src/main/resources/db/migration/V25__create_todo_items_table.sql`**

[`V6__create_raid_items_table.sql`](../../backend/src/main/resources/db/migration/V6__create_raid_items_table.sql)을 본보기로 씁니다.
PostgreSQL과 H2에서 모두 도는 문법만 씁니다(`BIGINT GENERATED BY DEFAULT AS IDENTITY`, 표준 FK).

```sql
CREATE TABLE todo_items (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    project_id BIGINT NOT NULL,
    title VARCHAR(255) NOT NULL,
    priority VARCHAR(20) NOT NULL,
    assignee_member_id BIGINT,
    due_date DATE,
    memo VARCHAR(2000),
    completed_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL,
    CONSTRAINT fk_todo_project FOREIGN KEY (project_id) REFERENCES projects (id) ON DELETE CASCADE,
    CONSTRAINT fk_todo_assignee FOREIGN KEY (assignee_member_id) REFERENCES project_members (id) ON DELETE SET NULL
);
CREATE INDEX idx_todo_project ON todo_items (project_id);
```

마이그레이션 상단에 왜 `SET NULL`이고 왜 `completed_at` 하나인지 주석을 답니다(V6과 같은 문체).
