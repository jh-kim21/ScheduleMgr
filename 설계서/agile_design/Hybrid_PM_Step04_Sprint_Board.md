# Step 04. Sprint 및 Board 구현

> 이 문서를 Agent에게 전달하여 해당 단계만 수행한다.

## 선행 조건

Step 3 완료. Backlog와 Work Package 귀속 검증 가능.

## Agent 공통 지침

- 실제 구현 대상 저장소에서 작업한다. 저장소의 AGENTS.md와 작업 지침을 먼저 확인한다.
- 전체 참고 문서는 `WBS_Agile_Hybrid_PM_Design.md`이다. 이 파일은 이번 단계 지시서이며 전체 설계를 한 번에 구현하지 않는다.
- 이전 단계 보고서와 실제 코드 상태를 함께 확인한다. 보고서만으로 구현 완료를 가정하지 않는다.
- 기존 기술 스택과 패턴을 사용한다. 관련 없는 리팩터링이나 새로운 플랫폼 도입은 하지 않는다.
- 사용자 변경 사항을 보존한다. 운영 데이터 변경, 배포, 외부 서비스 연결은 이번 작업에 포함하지 않는다.
- 다음 단계에 필요한 작은 내부 준비는 가능하지만 다음 단계의 기능을 선행 구현하지 않는다.
- 해결 가능한 구현 선택은 기존 코드에 맞춰 결정하고 근거를 기록한다. 선행 기능이 없으면 필요한 최소 보완 범위를 보고하며 대규모 확장을 진행하지 않는다.
- 보고서는 저장소의 기존 문서 규칙을 따르되 별도 규칙이 없으면 `docs/hybrid-pm/` 아래에 저장한다.
- 완료 시 변경 내용, 검증 명령과 결과, 미실행 검증과 이유, 남은 문제를 요약한다. **이 Step만 완료한 뒤 종료하고 다음 Step을 자동 실행하지 않는다.**

## 목표

Sprint 계획부터 Board 실행, 종료와 미완료 이월까지 한 흐름으로 관리한다.

## 수행 작업

1. Agile 하위에 Sprint와 Board를 추가한다.
2. Sprint의 팀, 이름, Goal, 기간, 계획·진행·종료 상태를 관리한다. 팀 모델이 없으면 최소 팀 범위를 정하고 기본 팀 도입 여부를 기록한다.
3. 연결된 Story·Bug를 Sprint에 배정한다. 여러 Work Package의 항목을 하나의 Sprint에 포함할 수 있게 한다.
4. 미연결 항목과 Epic의 배정을 차단한다. Task는 부모 항목을 통해 실행 상세로 표시한다.
5. Board 상태를 To Do → In Progress → Review → Done으로 제공하고, 기존 상태가 있으면 의미를 보존하여 매핑한다.
6. 차단 여부·차단 사유를 별도 속성으로 관리한다. RAID 연결 UI는 Step 6에서 추가한다.
7. 수용 조건과 완료 기준을 확인하는 최소 완료 절차를 구현한다. Task 완료만으로 Story를 자동 완료하지 않는다.
8. Sprint 배정과 제거, 시작 시 추정값, 종료 시 결과를 보존한다.
9. 미완료 항목은 원 Sprint에 미완료 결과를 남기고 재배정한다. 중복 배정과 완료 실적 중복 계산을 방지한다.
10. 완료 항목 재오픈 시 현재 상태와 과거 Sprint 종료 결과를 구분한다.

## 범위 제외

WBS 진척 자동 집계, 속도 기반 자동 일정 예측, Dashboard, 고급 용량 최적화.

## 검증 및 완료 기준

- Sprint 생성 → 항목 배정 → 실행 → 종료 → 미완료 이월을 확인한다.
- 동일 항목의 중복 배정과 두 활성 Sprint 동시 배정을 차단한다.
- 프로젝트·팀·기간 관련 유효성 검증과 기존 접근 권한을 확인한다.
- 재배정해도 과거 Sprint 결과가 변경되거나 완료 실적이 중복되지 않는다.
- Done 조건 미충족과 재오픈 흐름을 검증한다.
