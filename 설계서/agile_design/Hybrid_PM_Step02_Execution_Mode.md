# Step 02. WBS Execution Mode 추가

> 이 문서를 Agent에게 전달하여 해당 단계만 수행한다.

## 선행 조건

Step 1 분석 완료. Work Package 구분과 기존 데이터 처리 방안 확인.

## Agent 공통 지침

- 실제 구현 대상 저장소에서 작업한다. 저장소의 AGENTS.md와 작업 지침을 먼저 확인한다.
- 전체 참고 문서는 `WBS_Agile_Hybrid_PM_Design.md`이다. 이 파일은 이번 단계 지시서이며 전체 설계를 한 번에 구현하지 않는다.
- 이전 단계 보고서와 실제 코드 상태를 함께 확인한다. 보고서만으로 구현 완료를 가정하지 않는다.
- 기존 기술 스택과 패턴을 사용한다. 관련 없는 리팩터링이나 새로운 플랫폼 도입은 하지 않는다.
- 사용자 변경 사항을 보존한다. 운영 데이터 변경, 배포, 외부 서비스 연결은 이번 작업에 포함하지 않는다.
- 다음 단계에 필요한 작은 내부 준비는 가능하지만 다음 단계의 기능을 선행 구현하지 않는다.
- 해결 가능한 구현 선택은 기존 코드에 맞춰 결정하고 근거를 기록한다. 선행 기능이 없으면 필요한 최소 보완 범위를 보고하며 대규모 확장을 진행하지 않는다.
- 보고서는 저장소의 기존 문서 규칙을 따르되 별도 규칙이 없으면 `docs/hybrid-pm/` 아래에 저장한다.
- 완료 시 변경 내용, 검증 명령과 결과, 미실행 검증과 이유, 남은 문제를 요약한다. **이 Step만 완료한 뒤 종료하고 다음 Step을 자동 실행하지 않는다.**

## 목표

기존 WBS 기능을 유지하면서 Work Package에 Waterfall·Agile·Hybrid 실행 방식을 저장하고 표시한다.

## 수행 작업

1. Step 1 보고서의 변경 대상과 실제 코드를 확인한다.
2. 기존 최하위 작업 구분을 재사용한다. 구분이 없으면 Work Package를 식별하는 최소 구조를 추가하고, 자식 추가 시 규칙도 정한다.
3. Work Package에 실행 방식 값을 추가한다. 상위 WBS는 자식 실행 방식의 요약을 표시하고 독립 실행 실적을 갖지 않게 한다.
4. 기존 레코드는 기존 동작이 유지되는 기본값으로 처리한다. 기본값 선택 근거를 보고한다.
5. WBS 생성·수정·조회 화면과 저장 계층을 연결한다.
6. 기존 가져오기·내보내기가 있으면 필드 누락 시 하위 호환 처리와 새 필드 보존을 반영한다.
7. 실행 방식 변경 이력을 기존 방식으로 남긴다. 이력 기능이 없다면 해당 변경에 필요한 최소 이력만 추가한다.

## 범위 제외

Backlog, Sprint, Board, 새 진행률 계산, Dashboard 구현. 실행 방식을 선택했다는 이유로 기존 진척 데이터를 초기화하지 않는다.

## 검증 및 완료 기준

- 기존 레코드와 신규 레코드 모두 조회·수정·재조회가 가능하다.
- 유효하지 않은 실행 방식과 상위 노드에 대한 잘못된 설정을 검증한다.
- 기존 WBS 계층 편집과 진행률 동작이 유지된다.
- 마이그레이션이 있으면 개발용 데이터로 적용과 되돌리기 가능성을 확인한다.
- 기존 가져오기·내보내기가 있다면 구형 입력과 새 필드 왕복을 확인한다.
