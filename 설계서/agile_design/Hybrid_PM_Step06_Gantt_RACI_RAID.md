# Step 06. Gantt·RACI·RAID 연계

> 이 문서를 Agent에게 전달하여 해당 단계만 수행한다.

## 선행 조건

Step 5 완료. 공통 진척 조회와 기준·현재 일정 구분 가능.

## Agent 공통 지침

- 실제 구현 대상 저장소에서 작업한다. 저장소의 AGENTS.md와 작업 지침을 먼저 확인한다.
- 전체 참고 문서는 `WBS_Agile_Hybrid_PM_Design.md`이다. 이 파일은 이번 단계 지시서이며 전체 설계를 한 번에 구현하지 않는다.
- 이전 단계 보고서와 실제 코드 상태를 함께 확인한다. 보고서만으로 구현 완료를 가정하지 않는다.
- 기존 기술 스택과 패턴을 사용한다. 관련 없는 리팩터링이나 새로운 플랫폼 도입은 하지 않는다.
- 사용자 변경 사항을 보존한다. 운영 데이터 변경, 배포, 외부 서비스 연결은 이번 작업에 포함하지 않는다.
- 다음 단계에 필요한 작은 내부 준비는 가능하지만 다음 단계의 기능을 선행 구현하지 않는다.
- 해결 가능한 구현 선택은 기존 코드에 맞춰 결정하고 근거를 기록한다. 선행 기능이 없으면 필요한 최소 보완 범위를 보고하며 대규모 확장을 진행하지 않는다.
- 보고서는 저장소의 기존 문서 규칙을 따르되 별도 규칙이 없으면 `docs/hybrid-pm/` 아래에 저장한다.
- 완료 시 변경 내용, 검증 명령과 결과, 미실행 검증과 이유, 남은 문제를 요약한다. **이 Step만 완료한 뒤 종료하고 다음 Step을 자동 실행하지 않는다.**

## 목표

기존 일정·책임·통제 화면을 실행 데이터에 연결한다. 세 영역을 아래 순서로 각각 검증한다.

## 수행 작업

### 6-A. 간트 차트

- WBS 기준 일정, 현재 계획·예상 종료, 실제 실적을 구분한다.
- 팀별 Sprint 구간을 별도 레인에 표시하고 WBS 선택 시 관련 Sprint를 강조한다.
- Sprint가 여러 WBS에 관련되어도 일정과 진척을 중복 생성하지 않는다.
- 기준 종료일을 초과하는 예상 종료일을 경고하고 원본 항목으로 이동하게 한다.
- 기존 의존성과 마일스톤을 유지한다. Sprint 종료일을 WBS 실제 완료일로 자동 복사하지 않는다.
- 기준 일정 미등록 시 미등록 상태를 명시하고 현재 계획을 Baseline으로 표시하지 않는다.

### 6-B. RACI

- Work Package별 역할을 연결하고 상위 상속·하위 재정의 여부를 표시한다.
- A는 한 명을 기본 정책으로 하되 기존 데이터의 복수 A는 조용히 삭제하지 않고 정리 대상으로 알린다.
- Story 담당자·Reviewer와 RACI를 구분한다.
- Story 담당자 변경으로 WBS의 A나 권한을 자동 변경하지 않는다.

### 6-C. RAID

- 기존 RAID 유형 의미를 확인하고 그대로 유지·매핑한다. 문서 예시 때문에 기존 분류를 바꾸지 않는다.
- 하나의 RAID 항목을 여러 WBS·Sprint·Backlog에 연결한다.
- Board 차단 항목에서 관련 Issue와 담당자를 확인할 수 있게 한다.
- 일정 의존성과 RAID를 구분하고 연관 관계만 연결한다.
- 연결 대상 보관·삭제 시 참조 정책을 적용한다.

## 범위 제외

Dashboard 신규 구현, 알림 발송, 외부 협업 도구 연동, 자동 위험 판단, RACI 기반 권한 체계 전면 개편.

## 검증 및 완료 기준

- Gantt → WBS → Backlog → Sprint 이동이 동일 프로젝트 안에서 동작한다.
- 기준 일정이 현재 계획 수정으로 덮어써지지 않는다.
- Sprint 중복 표시가 집계 중복을 만들지 않는다.
- RACI 상속·재정의 및 담당자 변경 분리를 확인한다.
- RAID 복수 연결, 잘못된 프로젝트 연결 차단, 차단 Issue 추적을 확인한다.
