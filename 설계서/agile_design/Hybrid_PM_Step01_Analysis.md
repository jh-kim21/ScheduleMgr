# Step 01. 기존 구조 분석 및 구현 계획

> 이 문서를 Agent에게 전달하여 해당 단계만 수행한다.

## 선행 조건

없음. 실제 구현 저장소와 전체 설계 문서에 접근할 수 있어야 한다.

## Agent 공통 지침

- 실제 구현 대상 저장소에서 작업한다. 저장소의 AGENTS.md와 작업 지침을 먼저 확인한다.
- 전체 참고 문서는 `WBS_Agile_Hybrid_PM_Design.md`이다. 이 파일은 이번 단계 지시서이며 전체 설계를 한 번에 구현하지 않는다.
- 이전 단계 보고서와 실제 코드 상태를 함께 확인한다. 보고서만으로 구현 완료를 가정하지 않는다.
- 기존 기술 스택과 패턴을 사용한다. 관련 없는 리팩터링이나 새로운 플랫폼 도입은 하지 않는다.
- 사용자 변경 사항을 보존한다. 운영 데이터 변경, 배포, 외부 서비스 연결은 이번 작업에 포함하지 않는다.
- 다음 단계에 필요한 작은 내부 준비는 가능하지만 다음 단계의 기능을 선행 구현하지 않는다.
- 해결 가능한 구현 선택은 기존 코드에 맞춰 결정하고 근거를 기록한다. 선행 기능이 없으면 필요한 최소 보완 범위를 보고하며 대규모 확장을 진행하지 않는다.
- 보고서는 저장소의 기존 문서 규칙을 따르되 별도 규칙이 없으면 `docs/hybrid-pm/` 아래에 저장한다.
- 완료 시 변경 내용, 검증 명령과 결과, 미실행 검증과 이유, 남은 문제를 요약한다. **이 Step만 완료한 뒤 종료하고 다음 Step을 자동 실행하지 않는다.**

## 목표

현재 구현을 확인하여 재사용 범위와 단계별 변경 순서를 정한다. **이번 단계에서는 애플리케이션 코드와 DB를 변경하지 않는다.**

## 수행 작업

1. 기술 스택, 실행 방법, 테스트 방식, 저장소 구조를 확인한다.
2. 프로젝트·WBS·간트 차트·RACI·RAID의 화면, API, 저장 방식과 관련 파일을 조사한다.
3. 프로젝트별 데이터 격리, WBS 계층과 최하위 작업 구분, 수동·자동 진행률, 일정·Baseline, 담당자·권한, 가져오기·내보내기를 확인한다.
4. 기존 데이터 형식과 마이그레이션 방식을 확인한다. 운영 데이터 대신 스키마와 개발용 예시로 분석한다.
5. 전체 설계와의 차이를 표로 정리한다. 확인된 사실과 미확인 사항을 구분한다.
6. Step 2의 수정 대상, 기존 데이터의 실행 방식 기본값, 롤백 방법과 검증 항목을 제안한다.
7. Step 5의 선행 조건인 가중치·완료 기준·Baseline·변경 이력의 현재 지원 여부를 확인한다. 없으면 Step 5 내부에서 순차 처리할 최소 범위를 제시한다.

## 범위 제외

기능 구현, DB 마이그레이션 실행, 패키지 업데이트, 광범위한 리팩터링.

## 검증 및 완료 기준

- 주요 화면에서 데이터 저장까지의 연결을 실제 파일 경로로 설명한다.
- 기존 실행·검증 방법을 확인하고 실행했다면 결과를 기록한다.
- 7개 단계의 의존 관계와 Step 2의 구체적 수정 대상이 명시되어 있다.
- 필수 의사결정과 Agent가 판단 가능한 구현 선택을 분리한다.
