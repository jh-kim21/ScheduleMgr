# Step 07. Dashboard 및 통합 검증

> 이 문서를 Agent에게 전달하여 해당 단계만 수행한다.

## 선행 조건

Step 6 완료. 일정·진척·Sprint·RACI·RAID의 연결과 공통 조회 가능.

## Agent 공통 지침

- 실제 구현 대상 저장소에서 작업한다. 저장소의 AGENTS.md와 작업 지침을 먼저 확인한다.
- 전체 참고 문서는 `WBS_Agile_Hybrid_PM_Design.md`이다. 이 파일은 이번 단계 지시서이며 전체 설계를 한 번에 구현하지 않는다.
- 이전 단계 보고서와 실제 코드 상태를 함께 확인한다. 보고서만으로 구현 완료를 가정하지 않는다.
- 기존 기술 스택과 패턴을 사용한다. 관련 없는 리팩터링이나 새로운 플랫폼 도입은 하지 않는다.
- 사용자 변경 사항을 보존한다. 운영 데이터 변경, 배포, 외부 서비스 연결은 이번 작업에 포함하지 않는다.
- 다음 단계에 필요한 작은 내부 준비는 가능하지만 다음 단계의 기능을 선행 구현하지 않는다.
- 해결 가능한 구현 선택은 기존 코드에 맞춰 결정하고 근거를 기록한다. 선행 기능이 없으면 필요한 최소 보완 범위를 보고하며 대규모 확장을 진행하지 않는다.
- 보고서는 저장소의 기존 문서 규칙을 따르되 별도 규칙이 없으면 `docs/hybrid-pm/` 아래에 저장한다.
- 완료 시 변경 내용, 검증 명령과 결과, 미실행 검증과 이유, 남은 문제를 요약한다. **이 Step만 완료한 뒤 종료하고 다음 Step을 자동 실행하지 않는다.**

## 목표

프로젝트 Dashboard를 제공하고 실제 사용자 흐름을 끝까지 검증한다.

## 수행 작업

1. 기존 프로젝트 목록을 유지하고 프로젝트 선택 후 Dashboard 진입을 제공한다.
2. 전체 진척, 기준 계획 진척과 편차, 예상 종료·마일스톤, Sprint Goal·완료·차단 항목을 표시한다.
3. Work Package 상태, 열린 Issue·주요 위험·기한 초과 Action, 범위 변화와 데이터 누락을 표시한다. RAID 유형은 실제 시스템의 의미에 맞춘다.
4. 종료 Sprint의 팀별 완료 Story Point 추세를 표시한다. 진행 중 Sprint와 구분하고 팀 간 포인트를 합산하지 않는다.
5. 각 지표에 기준일과 상세 목록 이동을 제공한다.
6. 동일 범위·가중치 기준에서만 계획 대비 실제 진척을 비교한다. 미산정 값은 0으로 대체하지 않는다.
7. 프로젝트 전체 흐름과 기존 가져오기·내보내기를 검증한다. 연결 데이터 누락이 있으면 기존 구조에 맞는 최소 보완을 한다.
8. 주요 사용자 흐름, 실행·검증 방법, 알려진 제한 사항을 문서화한다.

## 통합 검증 시나리오

- 프로젝트 생성 → WBS 구성 → 실행 방식 지정 → Backlog 연결 → Sprint 배정 → Board 완료 → WBS 진척 반영.
- 미완료 이월 → 다음 Sprint 완료 → 과거 결과 보존 및 중복 실적 방지.
- Hybrid의 개발 완료 → 인수 대기 → 승인 후 최종 완료.
- 일정 지연 → 관련 Backlog·RAID 원인 확인 → 책임자 확인.
- 범위·가중치 변경 → 현재 진척 갱신 → 기준 버전과 과거 보고 보존.
- 프로젝트 변경 → 모든 화면의 필터·접근 범위 갱신.
- 기존 프로젝트 데이터 조회·수정 및 가져오기·내보내기 회귀 확인.

## 검증 및 완료 기준

- 같은 프로젝트·범위·기준일의 WBS, 간트 차트, Dashboard 진척이 일치한다.
- 빈 데이터·미산정·오류·접근 불가 상태를 적절하게 표시한다.
- 숫자에서 원인 항목으로 이동 가능하고 기존 메뉴가 정상 동작한다.
- 저장소의 관련 테스트와 필수 빌드·검사를 실행한다. 실패 또는 미실행 항목을 숨기지 않는다.
- 완료 조건에 영향을 주는 결함은 수정 후 재검증한다. 환경 제약으로 검증 못 한 기능은 완료로 단정하지 않는다.
