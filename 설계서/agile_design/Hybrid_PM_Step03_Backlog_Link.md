# Step 03. Backlog와 Work Package 연결

> 이 문서를 Agent에게 전달하여 해당 단계만 수행한다.

## 선행 조건

Step 2 완료. Work Package 식별 및 Execution Mode 저장·조회 가능.

## Agent 공통 지침

- 실제 구현 대상 저장소에서 작업한다. 저장소의 AGENTS.md와 작업 지침을 먼저 확인한다.
- 전체 참고 문서는 `WBS_Agile_Hybrid_PM_Design.md`이다. 이 파일은 이번 단계 지시서이며 전체 설계를 한 번에 구현하지 않는다.
- 이전 단계 보고서와 실제 코드 상태를 함께 확인한다. 보고서만으로 구현 완료를 가정하지 않는다.
- 기존 기술 스택과 패턴을 사용한다. 관련 없는 리팩터링이나 새로운 플랫폼 도입은 하지 않는다.
- 사용자 변경 사항을 보존한다. 운영 데이터 변경, 배포, 외부 서비스 연결은 이번 작업에 포함하지 않는다.
- 다음 단계에 필요한 작은 내부 준비는 가능하지만 다음 단계의 기능을 선행 구현하지 않는다.
- 해결 가능한 구현 선택은 기존 코드에 맞춰 결정하고 근거를 기록한다. 선행 기능이 없으면 필요한 최소 보완 범위를 보고하며 대규모 확장을 진행하지 않는다.
- 보고서는 저장소의 기존 문서 규칙을 따르되 별도 규칙이 없으면 `docs/hybrid-pm/` 아래에 저장한다.
- 완료 시 변경 내용, 검증 명령과 결과, 미실행 검증과 이유, 남은 문제를 요약한다. **이 Step만 완료한 뒤 종료하고 다음 Step을 자동 실행하지 않는다.**

## 목표

Agile 메뉴와 Backlog를 추가하고 실행 항목을 단일 Work Package에 연결한다.

## 수행 작업

1. 기존 프로젝트 선택 컨텍스트를 유지하는 Agile / Backlog 메뉴를 추가한다.
2. Epic·Story·Bug 및 하위 Task를 기존 구조에 맞춰 모델링한다. Product Backlog는 목록이며 별도 계층 노드로 만들지 않는다.
3. 제목, 유형, 우선순위, 상태, 담당자, 수용 조건, Story Point, 진척 가중치를 관리한다. Story Point와 진척 가중치는 서로 다른 값이다.
4. 집계 대상 Story·Bug는 하나의 Work Package에 귀속시킨다. Epic은 한 Work Package 내에서 사용하고 하위 항목도 동일 귀속을 유지한다.
5. Epic 없이 Story·Bug를 직접 연결할 수 있게 한다. Task는 부모 항목의 Work Package 귀속을 따른다.
6. 초안의 미연결 상태는 허용할 수 있지만 명확히 표시한다. Sprint 투입 전 연결 필수 검증을 다음 단계에서 사용할 수 있게 한다.
7. WBS에서 연결 항목 수를 클릭하면 필터링된 Backlog로 이동하고, Backlog에서 원본 WBS로 이동하게 한다.
8. 삭제·재귀속 시 연결 손실을 방지하고 변경 이력을 보존한다. Waterfall 항목의 Agile 실행 연결은 실행 방식 변경이 필요함을 안내한다.

## 범위 제외

Sprint 배정, Board, 자동 진행률, Epic의 여러 Work Package 귀속, 외부 이슈 도구 연동.

## 검증 및 완료 기준

- Backlog 생성·수정·조회·보관 및 WBS 필터 이동을 확인한다.
- 프로젝트가 다른 WBS 연결, Summary 연결, 부모 순환, 상하위 귀속 불일치를 차단한다.
- 기존 프로젝트 접근 권한을 API 또는 저장 계층에서도 적용한다.
- 연결 항목이 있는 WBS 삭제가 조용히 데이터를 유실시키지 않는다.
- Epic·Task를 향후 진척 집계에서 제외할 수 있도록 집계 단위가 구분된다.
