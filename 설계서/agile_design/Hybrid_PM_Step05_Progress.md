## 목표

범위와 가중치 기준을 보존하면서 실행 방식별 진척과 상위 WBS 진척을 일관되게 계산한다.

## 내부 작업 순서

이번 Step은 아래 순서로 진행한다. 각 묶음의 검증이 끝난 뒤 다음 묶음으로 넘어간다.

### 5-A. 집계 기준 준비

- Work Package의 형제 간 가중치, Backlog 내부 가중치, 체크포인트 완료 조건을 구분한다.
- Waterfall 승인 체크포인트와 Hybrid 비중을 구현한다.
- 기존 Baseline·변경 이력을 재사용한다. 없다면 승인 범위·일정·가중치·완료 기준의 버전과 변경 사유를 보존하는 최소 구조를 추가한다.
- Baseline을 자동 승인하거나 실제 프로젝트에 임의 생성하지 않는다.
- 기존 수동 진척은 보존하고 자동 집계 전환 정책을 기록한다.

### 5-B. 공통 집계 구현

- Agile: 100 × 완료된 Story·Bug 가중치 합 / 집계 대상 전체 가중치 합.
- Waterfall: 100 × 승인된 체크포인트 가중치 합 / 전체 체크포인트 가중치 합.
- Hybrid: α × Agile 진척 + (1 − α) × Waterfall 진척. 두 구성 요소의 중복 반영을 금지한다.
- 상위 WBS: Σ(직계 자식 가중치 × 자식 진척) / Σ(직계 자식 가중치).
- Epic·Task·기본 가중치 없는 Milestone은 별도 가산하지 않는다.
- Story Point를 WBS 가중치로 변환하지 않는다.
- 분모 0이나 미구성 범위는 산정 전으로 표시한다. 부모에서 조용히 제외하거나 0%로 단정하지 않고 집계 불완전 상태를 전파한다.
- 실행 진척과 최종 인수 상태를 분리한다.
- 재오픈·추가·취소·가중치 변경 시 현재 결과를 재계산한다.

### 5-C. 화면과 보고 일관성

- WBS에 공통 계산 결과를 적용하고 다른 화면이 같은 결과를 조회할 수 있게 한다.
- 보고일·Baseline·범위·정책 버전이 포함된 최소 진척 스냅샷을 저장한다.
- 기준 범위와 현재 범위를 구분한다. 계획 진척은 승인된 체크포인트 또는 계획 곡선이 있을 때만 계산하고, 없으면 미산정으로 표시한다.
- 시간 경과를 실제 진척으로 사용하지 않는다.

## 범위 제외

고급 일정 예측, EVM, 전체 Dashboard, 대규모 이벤트 아키텍처. 기본 구현은 기존 저장 구조와 동기 집계를 우선한다.

## 검증 및 완료 기준

- 동일 가중치 10개 중 6개 완료 시 60%이다.
- 자식 가중치 20·50·30, 진척 80·40·60이면 부모 54%이다.
- Hybrid 비중 0.7, Agile 80%, Waterfall 50%이면 71%이다.
- 분모 0, 미산정 자식, 재오픈, 범위 변경, Epic·Task 중복 제외를 검증한다.
- 기존 수동 실적·Baseline·과거 스냅샷이 보존된다.
- 진척 100%와 인수 완료 상태를 구분하고 반올림은 표시 단계에만 적용한다.
