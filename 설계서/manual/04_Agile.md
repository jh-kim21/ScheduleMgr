# 4. Agile — Backlog · Sprint · Board

> **한 줄 요약** — 세 화면은 하나의 흐름입니다. **Backlog에 적고 → Sprint에 담고 → Board에서 옮깁니다.**
> Backlog는 "무슨 일을 하는가", Sprint는 "이번 2주에 무엇을 하기로 했는가", Board는 "그 일이 지금
> 어디까지 왔는가"에 답합니다.

---

## 4.1 세 화면의 역할 분담

상단 메뉴에서 **Agile**을 누르면 Backlog로 이동하고, 그 아래에 `Backlog · Sprint · Board` 줄이
펼쳐집니다. Agile은 자기 화면이 없는 묶음 이름입니다.

| 화면 | 다루는 것 | 다루지 않는 것 |
|---|---|---|
| **Backlog** (`/backlog`) | 항목을 만들고, 유형·계층·귀속 Work Package·담당·추정을 정한다. 보관·삭제 | 어느 Sprint에 넣을지 |
| **Sprint** (`/sprint`) | Sprint 만들기, 항목 **배정**, **시작**(과 **시작 취소**), **종료**(이월 포함) | 카드 옮기기, 차단 |
| **Board** (`/board`) | 카드를 네 칸 사이로 옮기기, **차단** 표시, 배정 **제거** | Sprint 자체의 생성·시작·종료 |

세 화면이 나뉜 이유는 성격이 다르기 때문입니다. Backlog와 Sprint는 **계획**을 다루므로 표와 폼이
어울리고, Board는 **실행**을 다루므로 카드와 드래그가 어울립니다. Sprint 화면과 Board 화면은
**고른 Sprint를 공유**합니다 — Sprint 목록에서 고른 것이 Board를 열면 그대로 열려 있습니다.

**프로젝트 선택은 모든 화면이 공유합니다.** 화면을 옮겨도 유지됩니다.

> **한 항목은 세 화면에서 같은 것을 가리킵니다.** Board의 카드는 별도의 데이터가 아니라 Backlog
> 항목입니다. 그래서 Board에서 카드를 "검토"로 옮기면 Backlog 표의 상태 열도 함께 바뀝니다.

---

## 4.2 Backlog

실행할 일을 적는 목록입니다. WBS가 **범위**(무엇을 만드는가)라면 Backlog는 **실행**(그것을 어떤
일로 쪼개 하는가)입니다. 그래서 모든 항목은 WBS의 **최하위 Work Package**에 귀속됩니다.

### 4.2.1 화면 구성 (표 열·필터·버튼)

**맨 위**에 프로젝트 셀렉트가 있고, 불러오는 동안 `불러오는 중…`이 옆에 뜹니다.

#### 상단 안내와 배너

상황에 따라 아래가 표 위에 나타납니다. **배너의 건수는 필터를 무시하고 프로젝트 전체를 셉니다** —
"미연결 3건"은 프로젝트에 대한 사실이라, 필터 때문에 숫자가 줄면 문제가 작아 보이기 때문입니다.

| 표시 | 나오는 조건 |
|---|---|
| `실행 방식을 지정할 Work Package가 없습니다…` | WBS에 Work Package가 하나도 없음. WBS 화면 링크가 붙습니다 |
| **`미연결 N건`** | 귀속 Work Package가 없는 **비보관** 항목 수 |
| **`연결을 고쳐야 하는 항목 N건`** + 제목 나열 | 귀속 대상이 Summary가 되었거나 사라진 **비보관** 항목 |
| `Sprint에 넣을 수 없는 Story·Bug가 N건 있습니다` | 위 문제 때문에 배정이 막힌 Story·Bug 수 |
| `… 에 귀속된 항목만 보고 있습니다.` | Work Package 필터가 걸려 있을 때 |

#### 필터 (표 바로 위)

| 필터 | 값 |
|---|---|
| **Work Package** | 전체 / WBS 코드 + 이름 (Work Package만 나옵니다. Summary는 목록에 없습니다) |
| **유형** | 전체 / Epic / Story / Bug / Task |
| **상태** | 전체 / 할 일 / 진행 중 / 검토 / 완료 |
| **연결** | 연결 여부 전체 / 연결됨 / 미연결 |
| **보관** | **보관 제외**(기본) / 보관만 / 보관 포함 |

기본값에서 하나라도 달라지면 오른쪽에 **필터 해제** 버튼이 나타납니다. 필터는 화면을 떠나도
유지됩니다 — 떠날 때의 시야로 돌아오는 것이 상태를 기억하는 이유입니다.

> **보관은 기본으로 감춥니다.** 접어둔 항목이 섞이면 열린 일이 실제보다 많아 보입니다.
>
> **WBS 화면의 `연결 Backlog` 셀을 눌러 오면** 그 Work Package로 필터가 자동으로 걸리고,
> 이때만 **보관 포함**으로 바뀝니다. WBS에서 "보관 2"를 보고 눌렀는데 빈 목록이 나오면 안 되기
> 때문입니다. 주소창의 조건은 곧바로 지워지므로, 이후 필터를 손으로 바꿔도 되돌아가지 않습니다.

#### 표 열

**유형 · 제목 · 귀속 Work Package · 담당 · SP · 가중치 · 상태 · (수정 / 보관·복구 / 삭제)**

- **정렬은 우선순위(높음 → 보통 → 낮음) 다음 등록 순**이고, **가족이 한 덩어리로 붙습니다** —
  Epic 다음에 그 Story들, 각 Story 다음에 그 Task들. 제목 칸의 들여쓰기가 계층을 나타냅니다.
- **순서를 손으로 바꾸는 기능은 없습니다.** 위로 올리고 싶으면 우선순위를 높이세요.
- **귀속 Work Package 칸은 링크**입니다. 누르면 WBS 화면에서 그 항목이 펼쳐지고 강조됩니다.
- 필터에 걸리지 않았지만 **하위를 설명하려고 남긴 조상 행은 흐리게** 표시됩니다. Task 하나만
  검색되어도 그 Story가 무엇인지 보이게 하려는 것입니다.
- **제목 칸에는 칩과 표시가 여러 개 붙습니다** — [4.2.5](#425-경고-표시가-뜻하는-것) 참조.
- **수용 조건**이 있으면 제목 아래 작은 글씨로 함께 보입니다.

**＋ 항목 추가** 버튼은 필터 줄 오른쪽 끝에 있습니다.

### 4.2.2 항목 만들기와 입력 필드

**＋ 항목 추가**(또는 행의 **수정**)를 누르면 대화상자가 뜹니다.

| 필드 | 필수 | 설명 |
|---|---|---|
| **제목** | ● | 비어 있으면 저장되지 않습니다 |
| **유형** | ● | Epic / **Story**(기본) / Bug / Task |
| **우선순위** | ● | 높음 / **보통**(기본) / 낮음. **목록의 정렬 순서를 정합니다** |
| **상태** | ● | **할 일**(기본) / 진행 중 / 검토 / 완료 |
| **상위 항목** | Task만 | Task는 Story·Bug 아래에만, Story·Bug는 Epic 아래에만 놓입니다. Epic은 상위를 가질 수 없습니다 |
| **귀속 Work Package** | | 미연결(초안)로 둘 수 있습니다. **상위 항목을 고르면 잠기고** 상위 값이 들어갑니다 |
| **담당자** | | 프로젝트 구성원 중 하나. 미지정 가능 |
| **수용 조건** | | 완료로 인정하는 기준. 자유 입력이며 완료 확인 대화상자에 그대로 보여집니다 |
| **Story Point** | | 팀의 크기 추정. 0 이상 |
| **진척 가중치** | | 같은 Work Package 안에서의 비중. 0 이상 |
| **설명** | | 자유 입력 |
| **완료 확인 체크박스** | 조건부 | 상태를 **완료로 바꿀 때만** 나타납니다 |

폼이 상황에 따라 덧붙이는 안내:

- 상위를 골랐을 때 — `하위 항목의 귀속은 상위 항목을 따릅니다. 귀속을 바꾸려면 상위 항목을 옮기세요.`
- Task인데 상위가 없을 때 — `Task는 Story 또는 Bug의 하위여야 합니다.`
- Epic·Task를 고를 때 — `…은(는) 진척 집계에 별도로 가산되지 않습니다.`
- 귀속 Work Package의 실행 방식이 Agile·Hybrid가 아닐 때 — 실행 방식을 바꾸라는 안내. **막지는
  않습니다**(초안 단계에서는 정상적인 순서입니다).

> **Story Point와 진척 가중치는 다른 값입니다.** 포인트는 팀의 추정(속도 추세의 재료), 가중치는
> 진척 계산에서 이 항목이 차지하는 비중입니다. 같은 단위가 아니므로 더하거나 바꿔 쓰면 안 됩니다.

> **집계 대상은 Story와 Bug뿐입니다.** Epic은 묶음이고 Task는 실행 상세라, Epic을 그 안의 Story와
> 함께 세면 같은 일을 두 번 세게 됩니다. 그래서 Epic·Task 행에는 `집계 제외` 칩이 붙고, 이 둘은
> **Sprint에 배정할 수도 없습니다.**

#### 저장할 때의 동작

- **추가한 뒤에는 대화상자가 열린 채 남습니다.** 여러 건을 연달아 적는 것이 흔하고, 아래 표에
  새 행이 나타나는 것이 이미 확인 신호입니다. **수정한 뒤에는 닫힙니다.**
- **저장이 거부되면 닫히지 않고** 대화상자 안에 이유가 표시되며 입력값은 그대로 남습니다.
- 상태를 **완료**로 바꾸려면 확인 체크박스를 켜야 **저장 버튼이 활성**됩니다. 이미 완료인 항목을
  다시 저장할 때는 묻지 않습니다 — 제목만 고쳐도 매번 체크하게 만들지 않으려는 것입니다.
- **Esc로 닫을 수 있고**, 열리면 첫 입력 칸에 커서가 갑니다.

### 4.2.3 계층과 귀속 규칙

#### 계층은 두 단만

```text
Epic ── Story ── Task
   └── Bug  ── Task
```

- **Epic은 다른 항목의 하위가 될 수 없습니다.**
- **Story·Bug의 상위는 Epic뿐**이고, **Task의 상위는 Story 또는 Bug뿐**입니다.
- **Task는 상위 없이 존재할 수 없습니다.** Work Package에 직접 붙일 수 없습니다.
- 이미 하위를 가진 항목의 **유형을 바꿔서 그 하위가 갈 곳이 없어지면 거부**됩니다.
  (예: Task를 달고 있는 Story를 Epic으로 바꾸려는 경우)
- 자기 자신 또는 자기 하위를 상위로 지정하면 거부됩니다.

> **Epic·Story·Bug는 계층 노드가 아닙니다.** WBS처럼 `1.2.1` 같은 코드를 만들지 않고, 들여쓰기는
> 화면 표시일 뿐입니다.

#### 귀속은 상속됩니다 — 검증이 아니라 불가능

- 상위가 있는 항목의 귀속 Work Package는 **언제나 상위 것**입니다. 폼에서 그 셀렉트가 잠기는
  이유입니다.
- **상위를 다른 Work Package로 옮기면 하위 전체가 따라갑니다.** 그래서 Story를 다른 Epic 아래로
  옮기는 순간, 그 Story와 Task들의 귀속이 조용히 새 Epic의 것으로 바뀝니다 — 잠긴 셀렉트에
  바뀐 값이 보이니 저장 전에 확인하세요.
- **귀속은 최하위 Work Package에만 됩니다.** Summary를 지정하면 거부됩니다(셀렉트에 나오지도
  않습니다).
- 요청이 상위와 다른 Work Package를 지정하면 **조용히 고치지 않고 거부**합니다 — "Task를 다른
  Work Package로 옮겼다"고 착각하면 안 되기 때문입니다.

### 4.2.4 보관과 삭제

**다 쓴 항목은 삭제 대신 보관하세요.**

| | 보관 | 삭제 |
|---|---|---|
| 남는 것 | 항목 전체(마지막 상태 포함) | 아무것도 |
| 되돌리기 | **복구** 버튼 | 불가 |
| 표에서 | 기본 필터에서 감춰짐, 제목에 취소선 + `보관` 칩 | 사라짐 |
| 진척 집계 | 빠짐 | 빠짐 |
| Sprint 배정 | 배정 대상에서 제외 | — |

- **보관해도 상태는 그대로입니다.** 어느 상태에서 접었는지가 기록의 일부이기 때문입니다.
- **열려 있는 Sprint(계획 중 또는 실행 중)에 배정된 항목은 보관·삭제가 모두 거부됩니다.**
  버튼이 비활성되고 툴팁에 어느 Sprint인지 나옵니다. Sprint에서 **제거**(Board 화면)한 뒤 다시
  시도하세요. 그대로 지우면 그 Sprint의 배정 기록까지 사라지기 때문입니다.
- **하위 항목이 있으면 삭제할 수 없습니다.** 툴팁에 몇 건인지 나옵니다. 하위를 먼저 옮기거나
  지우세요. (보관은 하위가 있어도 됩니다.)
- **삭제에는 확인 대화상자가 없습니다.** 누르면 바로 지워집니다.
- 항목을 지우면 그 항목에 걸려 있던 **RAID 연결만 끊기고 RAID 항목 자체는 남습니다.**

> **WBS 쪽에서 오는 제약** — 살아 있는 Backlog가 붙어 있는 WBS 항목은 **삭제되지 않습니다.**
> 반대로 **보관된 항목만 남아 있으면** 연결을 끊고 지웁니다. 그래서 "WBS 항목을 지우고 싶은데
> Backlog가 붙어 있다"의 답은 **보관**입니다.

### 4.2.5 경고 표시가 뜻하는 것

제목 칸에 칩으로 붙습니다. **경고 칩은 한 번에 하나만** 보이고, 나쁜 것부터 우선합니다 —
아예 쓸 수 없는 연결이 실행 방식만 바꾸면 되는 것보다 급하기 때문입니다.

| 칩 | 뜻 | 무엇을 해야 하나 |
|---|---|---|
| **연결 끊김** | 귀속 id는 있는데 그 WBS 항목을 찾을 수 없다 | 수정에서 Work Package를 다시 고릅니다 |
| **Summary 연결** | 귀속 대상이 나중에 Summary로 바뀌었다 | 최하위 Work Package로 다시 연결합니다 |
| **미연결** | 귀속 Work Package가 없다 | 초안이면 정상. Sprint에 넣기 전에는 연결해야 합니다 |
| **실행 방식 확인** | 귀속 Work Package의 실행 방식이 Waterfall이거나 미지정 | WBS에서 Agile 또는 Hybrid로 바꿉니다. **배정은 막히지 않습니다** |

경고가 아닌 다른 칩들:

| 칩 | 뜻 |
|---|---|
| **보관** | 접어둔 항목. 제목에 취소선 |
| *(Sprint 이름)* | 그 열린 Sprint에 배정되어 있다. 보관·삭제가 막히는 이유 |
| **차단** | Board에서 차단 표시된 상태. 마우스를 올리면 사유가 보입니다 |
| **집계 제외** | Epic·Task. 진척에 별도로 가산되지 않습니다 |
| 높음 / 보통 / 낮음 | 우선순위. 높음은 붉게 표시됩니다 |

> **앞의 셋(연결 끊김·Summary 연결·미연결)이 있으면 Sprint에 배정할 수 없습니다.**
> `실행 방식 확인`은 경고일 뿐 배정을 막지 않습니다 — 고쳐야 할 상태이지 깨진 상태는 아닙니다.

## 4.3 Sprint

**계획**을 다루는 화면입니다. 만들고, 담고, 시작하고, 종료합니다.

### 4.3.1 화면 구성

**툴바** — 프로젝트 셀렉트 · `단일 팀` 배지(마우스를 올리면 이유가 뜹니다) · **＋ Sprint 추가**

**Sprint 목록** — 한 줄에 하나씩, **시작일이 늦은 것부터** 나옵니다. 지금 계획하거나 돌리고 있는
것이 맨 위에 있게 하려는 것입니다.

```text
Sprint 3   실행 중   2026-09-01 ~ 2026-09-12      4/9건 · 21/40 SP · 차단 1
```

| 부분 | 뜻 |
|---|---|
| 상태 | **계획** / **실행 중** / **종료** |
| `4/9건` | 완료 항목 / 배정 항목 |
| `21/40 SP` | 완료 Story Point / 배정 Story Point |
| `차단 N` | 차단된 항목 수 (0이면 표시 안 함, 열린 Sprint에서만 의미 있음) |
| `이월 N` | 이월된 항목 수 (0이면 표시 안 함, **종료된 Sprint에서만** 채워짐) |

**고른 Sprint의 상세**가 목록 아래에 펼쳐집니다.

- 이름 + 상태 배지
- 기간. **실행 중이면** `N일 남음` / `오늘 종료` / `종료일 N일 경과`가 붙습니다(종료일 포함 계산)
- 종료된 것이면 `종료 YYYY-MM-DD`
- `목표: …` 또는 `Sprint Goal이 비어 있습니다.`
- 오른쪽에 버튼들 — **시작 / 종료 / 시작 취소 / 수정 / 삭제** (상태에 따라 나타나는 것이 다릅니다)
- **항목 배정** 줄 (종료된 Sprint에는 없습니다)
- 맨 아래 **`이 Sprint 의 Board 열기`** 링크

**추가·수정 대화상자**의 필드는 **이름 · 시작일 · 종료일 · Sprint Goal** 넷뿐입니다. 종료일이
시작일보다 앞서면 저장 버튼이 비활성되고 그 자리에서 알려 줍니다.

### 4.3.2 계획 → 배정 → 시작 → 종료 흐름

```text
① ＋ Sprint 추가        이름·기간·목표          → 상태: 계획
② 항목 배정             셀렉트에서 골라 [배정]   → 여러 번 반복
③ [시작]                                        → 상태: 실행 중
   └─ [시작 취소]                                → 상태: 계획으로 되돌림 (배정은 그대로)
④ Board에서 실행        카드 이동·차단
⑤ [종료] + 이월 선택                            → 상태: 종료 (되돌릴 수 없음)
```

**② 배정** — `항목 배정` 셀렉트에는 `유형 · 제목 (N SP)` 형태로 나옵니다. 항목을 고르면 **배정**
버튼이 활성됩니다. 고를 것이 없으면 셀렉트에 `배정할 수 있는 항목이 없습니다`라고 적힙니다.

셀렉트에 나오는 것은 **완료 가능한 Story·Bug**이면서 **다른 열린 Sprint에 들어 있지 않은 것**뿐입니다.
구체적으로 아래를 모두 만족해야 합니다.

- 유형이 **Story 또는 Bug** (Epic·Task는 불가)
- **보관되지 않음**
- 귀속 Work Package가 **있고**, 그것이 **Summary가 아니고**, **사라지지도 않았음**
- 계획 중이든 실행 중이든 **다른 Sprint에 살아 있는 배정이 없음**

**③ 시작** — 시작하는 순간 배정된 항목들의 **Story Point가 그 시점 값으로 각인**됩니다. 계획
중에는 추정이 계속 바뀌므로, 기억할 값은 팀이 실제로 약속한 숫자이기 때문입니다. 이 값이 종료된
Sprint의 `계획 SP`가 됩니다.

**③ 시작 취소** — 실행 중인 Sprint에만 나오는 **되돌리기(undo)** 버튼입니다. 잘못 시작했거나
계획을 다시 잡아야 할 때 씁니다. 누르면 확인 대화상자가 뜹니다.

- 완료 항목이 없으면 가벼운 확인만 합니다: "각인된 Story Point가 지워집니다. 다시 시작하면 그
  시점 값으로 다시 찍힙니다."
- **완료 표시한 항목이 있으면** 그 건수를 밝히고 강하게 경고합니다: "이 Sprint에서 완료 표시한
  N건의 Sprint 기록이 사라집니다. **항목 자체의 완료 상태는 그대로 남습니다.**" — 뒷문장이
  중요합니다. 시작 취소는 Sprint의 기록(각인된 SP, 그 Sprint 안에서의 완료 실적)을 지우는
  것이지, Backlog 항목의 상태(할 일/진행 중/검토/완료)를 되돌리는 것이 아닙니다.
- **배정은 그대로 남습니다.** 다시 항목을 골라 담을 필요 없이 상태만 계획으로 돌아가므로,
  바로 다시 [시작]할 수 있습니다.
- 완료된 항목이 있어도 시작 취소 자체는 **막지 않습니다** — 경고는 화면이 하고, 결정은 사용자가
  합니다.

> **왜 종료가 아니라 시작 취소가 따로 있는가** — 시작 전에는 종료밖에 되돌릴 방법이 없었습니다.
> 그런데 잘못 시작한 Sprint를 그대로 종료하면, 실제로 하지 않은 일이 그 Sprint의 완료 실적으로
> 찍혀 **Dashboard의 속도 추세에 가짜 숫자가 영구히 남습니다**(종료된 Sprint의 숫자는 그 뒤
> 무슨 일이 있어도 움직이지 않기 때문입니다). 시작 취소는 실적을 남기지 않고 계획 단계로
> 돌아가는 것이라 이 문제가 생기지 않습니다.

**⑤ 종료** — 대화상자가 뜨고 아래를 알려 줍니다.

- 완료된 항목은 이 Sprint의 실적으로 기록되고, **미완료 항목 N건은 `이월`로 남습니다**
- **항목의 상태는 바뀌지 않습니다** — 종료는 Sprint의 진술이고, 일이 아직 검토에 있는지는 항목의
  사정입니다. 이 분리가 이월을 가능하게 합니다
- **미완료 항목을 옮길 Sprint**를 고를 수 있습니다(다음 절)

> **종료는 되돌릴 수 없습니다.** 종료된 Sprint는 수정·삭제·배정 변경·Board 이동이 모두 막히고,
> 그 숫자는 이후 무슨 일이 있어도 움직이지 않습니다.

### 4.3.3 이월 (실적이 두 번 세어지지 않는 이유 포함)

종료 대화상자의 **미완료 항목을 옮길 Sprint** 셀렉트에는 `지금은 옮기지 않음`과 **아직 종료되지
않은 다른 Sprint들**이 나옵니다. 옮길 곳이 하나도 없으면
`옮길 Sprint가 없습니다. 나중에 새 Sprint를 만들어 배정할 수 있습니다.`라고 적힙니다.

> ⚠️ **셀렉트의 기본값은 `지금은 옮기지 않음`이 아니라 목록의 첫 Sprint입니다.** 확인하지 않고
> 종료를 누르면 미완료 항목이 그 Sprint로 넘어갑니다. 옮기고 싶지 않다면 **직접 골라야 합니다.**

#### 종료할 때 각 항목에 찍히는 결과

| 결과 배지 | 언제 |
|---|---|
| **완료** | 종료 시점에 상태가 `완료`였다 |
| **이월** | 종료 시점에 완료가 아니었다 |
| **제외** | Sprint가 끝나기 전에 Board에서 **제거**했다 |

#### 왜 두 번 세어지지 않나

한 배정 행은 **한 Sprint의 한 항목**에 대한 기록이고, 종료할 때 그 행에 결과가 **한 번** 찍힙니다.
이월은 원래 행을 고치는 것이 아니라 **다음 Sprint에 새 행을 만드는 것**입니다.

```text
Sprint 3 : [Story A] → 종료 시 미완료 → 결과 "이월"   (완료 실적 0)
Sprint 4 : [Story A] 새 배정 행 → 여기서 완료 → 결과 "완료"  (완료 실적 1)
```

그래서 **Story A의 완료 실적은 Sprint 4에만 쌓입니다.** Dashboard의 속도 추세에서도 한 번만
셉니다.

**종료된 Sprint의 숫자는 그 뒤에 무슨 일이 있어도 변하지 않습니다.** 항목을 나중에 재오픈하거나
다른 Sprint에서 완료해도 마찬가지입니다 — 종료된 Sprint는 **자기가 찍어 둔 결과만** 말하고,
계획 SP도 시작 시점에 각인한 값을 씁니다.

### 4.3.4 이 화면의 규칙 (왜 버튼이 비활성인가)

| 버튼 | 언제 보이나 | 언제 비활성인가 / 왜 |
|---|---|---|
| **시작** | 상태가 **계획**일 때만 | **이미 실행 중인 Sprint가 있으면** 비활성. 툴팁: `이미 실행 중인 Sprint가 있습니다 (단일 팀)` |
| **종료** | 상태가 **실행 중**일 때만 | 항상 활성 |
| **시작 취소** | 상태가 **실행 중**일 때만 | 항상 활성. 완료 항목이 있어도 막지 않고, 대화상자에서 경고만 합니다 |
| **수정** | 종료가 **아닐** 때 | 항상 활성. 종료된 Sprint는 버튼 자체가 사라집니다(결과는 이력이므로) |
| **삭제** | 상태가 **계획**일 때만 | **배정된 항목이 하나라도 있으면** 비활성. 툴팁: `배정된 항목이 있어 삭제할 수 없습니다` |
| **배정** | 종료가 아닐 때 | 항목을 고르지 않으면 비활성 |

그 밖에 서버가 거부하는 것들 — 거부되면 화면 위쪽에 빨간 글씨로 이유가 나옵니다.

- **같은 이름의 Sprint를 두 개 만들 수 없습니다.**
- **종료일이 시작일보다 앞설 수 없습니다.**
- **실행 중인 Sprint는 삭제할 수 없습니다** — 먼저 종료해야 합니다. 종료된 것은 이력이라 지울 수
  없습니다.
- **종료된 Sprint에는 배정·제거·Board 이동이 되지 않습니다.**
- **한 항목은 열린 Sprint 하나에만 들어갑니다.** 계획 중인 다음 Sprint에 미리 넣어 두는 것도
  막습니다 — 지금 하는 일을 다음 계획에도 세면 계획이 두 배가 됩니다.
- **자기 자신으로는 이월할 수 없고, 종료된 Sprint로도 이월할 수 없습니다.**

> **왜 실행 중 Sprint가 하나뿐인가** — 이 앱은 한 프로젝트에 한 팀을 전제합니다. 팀이 하나면
> 동시에 도는 Sprint도 하나이고, 이 규칙이 "한 항목이 두 Sprint에서 동시에 세어지는 일"을
> 원천적으로 막아 줍니다. 툴바의 `단일 팀` 배지가 그 전제를 표시합니다.

## 4.4 Board

**실행**을 다루는 화면입니다. 카드를 네 칸 사이로 옮깁니다.

### 4.4.1 화면 구성 (네 칸과 카드에 보이는 것)

**툴바** — 프로젝트 셀렉트 · **Sprint 셀렉트**. Sprint 셀렉트에는 `이름 (상태)` 형태로 **모든
Sprint**가 나옵니다(계획·실행 중·종료 전부). 처음 들어오면 **실행 중인 Sprint**가 기본으로
열리고, 없으면 목록의 첫 번째가 열립니다. Sprint 화면에서 고른 것이 그대로 열립니다.

**헤더** — 이름 + 상태 배지, 기간(실행 중이면 남은 기간), `목표: …`, 오른쪽에
**`Sprint 계획으로`** 링크.

- 계획 상태이면 `아직 시작하지 않은 Sprint 입니다. 카드를 옮길 수는 있지만, 실적은 시작한 뒤부터
  의미가 있습니다.`
- Sprint가 하나도 없으면 Sprint 화면으로 가는 안내가 나옵니다.

**네 칸** — `할 일 · 진행 중 · 검토 · 완료`. 칸 머리에 그 칸의 카드 수가 적히고, 비어 있으면
`없음`이라고 표시됩니다. (화면이 좁으면 두 칸씩 두 줄로 접힙니다.)

#### 카드에 실제로 보이는 것

위에서부터 순서대로입니다. 해당 값이 없으면 그 줄은 나오지 않습니다.

| 위치 | 내용 |
|---|---|
| 머리 왼쪽 | **유형** (Epic / Story / Bug / Task) |
| 머리 오른쪽 | **Story Point** (없으면 표시 안 함) |
| 본문 | **제목** |
| | **WBS 코드 + Work Package 이름** |
| | **`차단: 사유`** (차단됐을 때. 사유가 없으면 `차단`만) |
| | **관련 RAID 목록** — 차단됐을 때만. `종류 · 제목 · 소유자` (소유자가 없으면 `소유자 미지정`) |
| | **`완료되지 않은 하위 N건`** |
| | **`지난 Sprint에서 완료로 기록된 항목입니다 (지금은 미완료).`** |
| 바닥 왼쪽 | **담당자** (없으면 `담당 미지정`) |
| 바닥 | **결과 배지** (완료 / 이월 / 제외 — 종료된 Sprint에서만) |
| 바닥 오른쪽 | **차단** 또는 **차단 해제** 버튼, **제거** 버튼 |

**종료된 Sprint의 Board는 읽기 전용입니다.** 카드를 끌 수 없고 차단·제거 버튼도 사라집니다.
대신 아래에 **`이 Sprint에서 제외된 항목 N건 — 제목들`** 이 표시됩니다 — 왜 빠졌는지가 이력이기
때문입니다. (열린 Sprint에서는 제거된 항목이 아예 보이지 않습니다.)

> **제거는 배정만 뺍니다.** Backlog 항목 자체는 그대로 남고, 그 Sprint의 기록에는 `제외`로
> 남습니다.

### 4.4.2 카드 옮기기와 완료 확인

**드래그해서 다른 칸에 놓습니다.** 놓을 수 있는 칸은 테두리가 강조됩니다. 카드를 옮기는 다른
방법(버튼·메뉴)은 없습니다.

**완료 칸으로 옮길 때만 확인 대화상자가 뜹니다.**

```text
완료 처리
  <카드 제목>
  수용 조건: …            ← 없으면 "등록된 수용 조건이 없습니다."
  완료되지 않은 하위가 N건 있습니다. 그래도 완료로 처리할 수 있습니다.   ← 하위가 남았을 때만
  수용 조건과 완료 기준(Definition of Done)을 확인했습니까?
  [확인하고 완료]  [취소]
```

- **왜 묻는가** — 시스템에 Definition of Done이 저장되어 있지 않습니다. 그러니 기준을 충족했다는
  것은 **누르는 사람만 증명할 수 있습니다.**
- **하위 Task를 다 끝내도 Story가 자동으로 완료되지 않습니다.** 대신 남은 하위 수를 카드와 이
  대화상자에 실어 사람이 판단하게 합니다. **하위가 남아 있어도 완료할 수 있습니다** — 불필요해진
  Task가 남는 것은 정상입니다.
- **완료에서 다른 칸으로 빼는 것(재오픈)은 묻지 않습니다.** 이때 완료 시각만 지워지고, **이미
  종료된 Sprint에 찍힌 `완료` 결과는 그대로 남습니다.** 그 상태가 되면 카드에
  `지난 Sprint에서 완료로 기록된 항목입니다 (지금은 미완료).`가 붙습니다 — 지금의 상태와 과거의
  실적은 다른 사실이기 때문입니다.
- **Backlog 편집 폼에서 상태를 완료로 바꿀 때도 같은 확인**을 요구합니다. 한쪽만 막으면 절차가
  장식이 되기 때문입니다.
- 계획 상태의 Sprint에서도 카드를 옮길 수는 있습니다(안내문이 뜹니다).

### 4.4.3 차단

카드 바닥의 **차단** 버튼을 누르면 사유를 적는 작은 대화상자가 뜹니다(예: `외부 API 응답 대기`).
사유는 **비워 둘 수 있습니다.**

- **차단은 칸(상태)과 별개입니다.** 카드는 있던 칸에 그대로 있고, 테두리가 붉어지며 사유가
  카드에 적힙니다. 상태를 한 칸 늘리지 않은 이유는 "차단"이 `할 일 → 진행 중 → 검토 → 완료`의
  중간에 끼어들면 흐름이 깨지기 때문입니다.
- **차단된 항목은 완료할 수 없습니다.** 먼저 **차단 해제**를 누르세요.
- **차단된 카드에만 관련 RAID가 펼쳐집니다.** 그 Backlog 항목에 직접 연결된 것과, 그 항목이
  귀속된 **Work Package**에 연결된 것을 함께 보여 주고, **종결된 RAID는 제외**합니다 — 이미 닫힌
  것은 아무것도 막고 있지 않기 때문입니다. 열려 있는 모든 카드에 위험 목록을 달면 보드가 읽히지
  않으므로 차단된 카드에만 폅니다.
- **차단은 Board를 통해서만 켜고 끕니다.** Backlog 표에서는 `차단` 칩으로 보이기만 하고 해제할
  수 없습니다. (여기서 오는 함정은 [발견한 결함](../발견한_결함.md) 참조.)

## 4.5 실무 예시

가상의 프로젝트 **"사내 예약 시스템"** 으로 2주 Sprint 한 사이클을 처음부터 끝까지 따라갑니다.

### 준비 — WBS와 실행 방식 (Agile 화면 이전)

WBS에 이렇게 만들어 두었다고 합시다.

```text
1   요구 분석            (Summary)
2   예약 기능            (Summary)
2.1   예약 등록 화면      (Work Package · 실행 방식: Agile)
2.2   예약 조회 API       (Work Package · 실행 방식: Agile)
3   배포                 (Work Package · 실행 방식: Waterfall)
```

구성원도 미리 등록합니다(RACI 화면 아래쪽) — `김PL`, `이개발`, `박QA`. 담당자 셀렉트는 여기서
등록한 사람만 보여 줍니다.

### 1일차 — Backlog 작성

**Backlog** 화면에서 **＋ 항목 추가**로 다음을 만듭니다.

| 유형 | 제목 | 상위 | 귀속 | 담당 | SP |
|---|---|---|---|---|---|
| Epic | 예약 흐름 | — | 2.1 예약 등록 화면 | — | — |
| Story | 사용자가 날짜를 골라 예약한다 | 예약 흐름 | *(상속: 2.1)* | 이개발 | 5 |
| Story | 예약 확인 메일을 받는다 | 예약 흐름 | *(상속: 2.1)* | 이개발 | 3 |
| Task | 메일 템플릿 작성 | 예약 확인 메일을… | *(상속: 2.1)* | 박QA | — |
| Bug | 중복 예약이 저장된다 | — | 2.2 예약 조회 API | 이개발 | 2 |
| Story | 관리자가 예약을 취소한다 | — | *(미연결)* | — | 8 |

여기서 일어나는 일:

- Epic을 상위로 고르는 순간 **귀속 셀렉트가 잠기고** `2.1 예약 등록 화면`이 자동으로 들어갑니다.
- Task는 상위를 고르지 않으면 저장되지 않습니다.
- 마지막 Story는 아직 어디에 붙일지 몰라 미연결로 뒀습니다. 화면 위에 **`미연결 1건`** 배너가
  뜨고, 행에 **`미연결`** 칩이 붙으며, **`Sprint에 넣을 수 없는 Story·Bug가 1건`** 이라고 알려
  줍니다.
- Epic 행과 Task 행에는 **`집계 제외`** 칩이 붙습니다.
- 표는 `높음 → 보통 → 낮음` 순으로 정렬되고, Epic 밑에 그 Story들이, Story 밑에 Task가 붙어
  나옵니다.

**미연결 Story를 정리합니다.** 수정을 눌러 귀속을 `2.2 예약 조회 API`로 지정하면 배너가
사라집니다.

### 2일차 — Sprint 계획과 시작

**Sprint** 화면 → **＋ Sprint 추가**

```text
이름        Sprint 1
시작일      2026-09-14
종료일      2026-09-25
Goal        예약 등록과 확인 메일까지 끝낸다
```

목록에서 `Sprint 1`을 고르고 **항목 배정** 셀렉트를 엽니다. 여기 나오는 것은 **Story 3건과
Bug 1건**뿐입니다 — Epic과 Task는 목록에 아예 없습니다.

세 건을 배정합니다(5 + 3 + 2 = 10 SP). 이제 목록 줄이 이렇게 보입니다.

```text
Sprint 1   계획   2026-09-14 ~ 2026-09-25    0/3건 · 0/10 SP
```

Backlog 화면으로 돌아가 보면 그 세 행에 **`Sprint 1`** 칩이 붙어 있고, **보관·삭제 버튼이
비활성**되어 있습니다.

**시작**을 누릅니다. 이 순간 10 SP가 각인됩니다. 상태가 `실행 중`이 되고, 다른 Sprint의 시작
버튼은 `이미 실행 중인 Sprint가 있습니다 (단일 팀)` 툴팁과 함께 비활성됩니다.

### 3~9일차 — Board에서 실행

**Board** 화면을 엽니다(Sprint 1이 이미 열려 있습니다). 헤더에 `9일 남음`이 보입니다.

- `사용자가 날짜를 골라 예약한다` 카드를 **할 일 → 진행 중**으로 끕니다. 확인 없이 바로 옮겨
  집니다.
- 며칠 뒤 **진행 중 → 검토 → 완료**로 옮깁니다. 완료로 놓는 순간 대화상자가 뜨고, 등록해 둔
  수용 조건이 그대로 보입니다. **확인하고 완료**를 누릅니다.
- `예약 확인 메일을 받는다`를 완료로 옮기려 하자 대화상자에
  **`완료되지 않은 하위가 1건 있습니다. 그래도 완료로 처리할 수 있습니다.`** 가 함께 뜹니다
  (Task `메일 템플릿 작성`이 남아 있습니다). 그 Task가 실제로는 필요 없어졌다고 판단하여 그대로
  완료합니다.

### 7일차 — 차단이 생기다

`중복 예약이 저장된다` Bug가 외부 DB 팀의 응답을 기다리게 됐습니다.

1. 카드의 **차단**을 누르고 사유에 `DB팀 유니크 제약 검토 대기`라고 적습니다.
2. 카드가 붉은 테두리로 바뀌고 사유가 카드에 적힙니다. **칸은 `진행 중` 그대로**입니다.
3. **RAID** 화면에서 이슈 `DB 유니크 제약 미확정`을 등록하고, 연결 대상으로 이 Bug(또는 귀속
   Work Package `2.2`)를 지정합니다.
4. Board로 돌아오면 차단 카드 아래에 그 이슈가 **소유자와 함께** 표시됩니다 — "왜 막혔나"의
   답이 카드 옆에 있습니다.
5. Sprint 목록 줄에도 `· 차단 1`이 붙습니다.

> 이 상태에서 카드를 완료로 끌면 확인 대화상자를 지나 **서버가 거부**하고, 화면 **맨 위**에
> `차단된 항목은 완료할 수 없습니다. 차단을 먼저 해제하세요.`가 뜹니다. 보드 아래쪽을 보고
> 있었다면 메시지를 놓치기 쉬우니, 완료 전에 **차단 해제**부터 누르세요.

### 10일차 — Sprint 종료와 이월

Bug는 끝내 풀리지 않았습니다. 종료 전에 **다음 Sprint를 먼저 만들어 둡니다.**

```text
Sprint 2   2026-09-28 ~ 2026-10-09   Goal: 예약 취소와 중복 예약 결함
```

Sprint 1을 고르고 **종료**를 누릅니다.

```text
Sprint 종료
  Sprint 1
  완료된 항목은 이 Sprint의 실적으로 기록되고, 미완료 항목(1건)은 이월로 남습니다.
  항목의 상태는 바뀌지 않습니다.

  미완료 항목을 옮길 Sprint  [ Sprint 2 (계획) ▾ ]    ← 기본값이 이미 Sprint 2입니다
  [종료]  [취소]
```

**종료** 후 결과:

```text
Sprint 1   종료   2026-09-14 ~ 2026-09-25    2/3건 · 8/10 SP · 이월 1
Sprint 2   계획   2026-09-28 ~ 2026-10-09    0/2건 · 0/10 SP
```

- Sprint 1의 Board는 **읽기 전용**이 됩니다. Bug 카드에 **`이월`** 배지가 붙습니다.
- Bug는 **Sprint 2에 새 배정으로 들어가 있습니다.** 상태는 여전히 `진행 중`이고 **차단도 그대로**
  입니다 — 종료는 항목의 상태를 건드리지 않습니다.
- 아직 배정하지 않은 `관리자가 예약을 취소한다`(8 SP)를 Sprint 2에 추가 배정합니다.

### 다음 사이클 — 실적이 두 번 세어지지 않는지 확인

Sprint 2를 시작하고, DB팀 회신이 와서 Bug 카드의 **차단 해제** 후 완료로 옮깁니다.
Sprint 2를 종료하면:

```text
Sprint 1   종료   2/3건 ·  8/10 SP · 이월 1      ← 그대로. 절대 움직이지 않습니다
Sprint 2   종료   2/2건 · 10/10 SP
```

**Bug의 완료 실적은 Sprint 2에만 쌓였습니다.** Dashboard의 완료 Story Point 추세도 `8 → 10`으로
그려지고, 같은 일을 두 번 세지 않습니다.

### 뒷정리

- 다 쓴 Epic이나 더 안 할 Story는 **삭제하지 말고 보관**하세요. 마지막 상태가 남고, 나중에
  `보관만` 필터로 다시 볼 수 있습니다.
- WBS에서 `2.1 예약 등록 화면`을 지우려 하면 **거부**됩니다. 붙어 있는 Backlog를 다른 Work
  Package로 옮기거나 보관한 뒤에 다시 시도하세요.

## 4.6 주의할 점

**계획과 실행이 섞이지 않게**

- **Story Point와 진척 가중치를 같은 것으로 쓰지 마세요.** 하나는 팀의 추정(속도의 재료),
  하나는 진척 계산에서의 비중입니다. 더하거나 바꿔 쓰면 두 숫자가 모두 의미를 잃습니다.
- **Epic·Task는 진척에도, Sprint에도 들어가지 않습니다.** 실행의 단위는 Story와 Bug입니다.
- **차단은 상태가 아닙니다.** 차단해도 카드는 그 칸에 남습니다. "지금 어느 단계인가"와
  "지금 막혀 있는가"는 다른 질문입니다.
- **보관도 상태가 아닙니다.** 보관해도 마지막 상태가 남습니다.

**되돌릴 수 없는 것**

- **Sprint 종료는 되돌릴 수 없습니다.** 종료 전에 이월 대상을 반드시 확인하세요 —
  **셀렉트의 기본값이 `지금은 옮기지 않음`이 아닙니다.**
- **Backlog 항목 삭제에는 확인 대화상자가 없습니다.** 지우기 전에 보관을 먼저 고려하세요.
- 이월할 Sprint가 필요하면 **종료하기 전에** 만들어 두는 편이 편합니다(나중에 배정해도 되지만,
  종료 대화상자에서 한 번에 끝내는 것이 흔한 흐름입니다).

**막혔을 때**

| 상황 | 이유와 대처 |
|---|---|
| 배정 셀렉트에 `배정할 수 있는 항목이 없습니다` | Story·Bug가 없거나, 미연결/Summary 연결이거나, 이미 다른 열린 Sprint에 있습니다. Backlog 화면의 경고 칩을 보세요 |
| Sprint **시작** 버튼이 비활성 | 이미 실행 중인 Sprint가 있습니다(단일 팀). 그것을 먼저 **종료**하거나(할 일이 끝났다면), 잘못 시작한 것이라면 **시작 취소**하세요 |
| Sprint **삭제** 버튼이 비활성 | 배정된 항목이 있습니다. Board에서 모두 제거하면 활성됩니다 |
| Backlog의 **보관·삭제** 버튼이 비활성 | 열린 Sprint(계획 중 포함)에 배정되어 있거나, 하위 항목이 있습니다. 툴팁에 이유가 있습니다 |
| 카드를 **완료로 옮길 수 없다** | 차단 상태입니다. **차단 해제**를 먼저 누르세요 |
| Backlog에서 **상태를 완료로 저장할 수 없다** | 확인 체크박스를 켜야 저장 버튼이 활성됩니다. 차단된 항목이면 그것부터 풀어야 합니다 |
| WBS 항목이 **삭제되지 않는다** | 살아 있는 Backlog가 붙어 있습니다. 옮기거나 **보관**하세요 |
| 다른 화면의 숫자가 낡아 보인다 | 화면마다 캐시가 있습니다. 그 화면으로 다시 들어가면 갱신됩니다 |

**Agile 밖으로 이어지는 것**

- **Board에서 완료해도 WBS의 실제 완료일은 채워지지 않습니다.** Sprint가 끝난 것과 산출물이
  완료된 것은 다른 사실이고, 한 Sprint가 여러 Work Package에 걸칠 수 있기 때문입니다.
- **간트의 Sprint 레인은 Sprint당 한 줄**입니다. 여러 Work Package에 걸쳐도 반복해 그리지
  않습니다.
- **Backlog 담당자는 RACI 역할이 아닙니다.** RACI 화면 행 머리에 참고로 보이지만, 담당자를
  바꿔도 그 업무의 A·R은 움직이지 않습니다.
- 귀속 Work Package의 실행 방식이 **Agile 또는 Hybrid**여야 Story·Bug의 완료가 진척으로
  올라갑니다. `실행 방식 확인` 칩이 보이면 WBS에서 먼저 바꾸세요.
