# 2. 프로젝트

> 모든 화면의 출발점. 프로젝트를 만들고 고르고, 파일로 주고받는 곳입니다.

## 2.1 화면 구성과 기본 작업

**표 열**: 이름(아래에 설명) · 상태 · 시작일 · 종료일 · (내보내기 / 수정 / 삭제)

| 하는 일 | 어디서 | 설명 |
|---|---|---|
| **＋ 프로젝트 추가** | 제목 오른쪽 | 대화상자가 열립니다 |
| **수정** | 행 오른쪽 | 같은 대화상자가 값이 채워진 채로 열립니다 |
| **삭제** | 행 오른쪽 | 브라우저 확인창 → [2.2](#22-프로젝트-삭제가-함께-지우는-것) |
| **내보내기** | 행 오른쪽 | 5가지 형식 → [9장](#9-내보내기와-가져오기) |
| **가져오기** | 화면 오른쪽 위 | 파일을 고르면 **새 프로젝트**가 생깁니다 |

### 입력 항목

| 필드 | 필수 | 설명 |
|---|---|---|
| **이름** | ✔ | 비우면 저장이 거부됩니다. 유일할 필요는 없지만, 목록에서 구분하려면 다르게 두는 편이 낫습니다 |
| **설명** | | 목록의 이름 아래에 회색 작은 글씨로 함께 보입니다 |
| **상태** | ✔ | 계획 / 진행중 / 보류 / 완료. 뱃지 색이 바뀔 뿐, **다른 화면의 계산에는 쓰이지 않습니다** |
| **시작일 · 종료일** | | 계획의 테두리입니다 |

> **프로젝트의 시작일·종료일은 어디에도 쓰이지 않습니다.**
> 간트와 Dashboard의 "계획 기간"은 이 두 날짜가 아니라 **WBS 항목들의 실제 날짜 범위**
> (가장 이른 시작일 ~ 가장 늦은 종료일)입니다. 둘이 어긋나 있어도 경고하지 않으므로,
> 프로젝트 기간을 적어 두었다고 일정이 그 안에 갇히지는 않습니다.

### 프로젝트 선택은 앱 전체가 공유합니다

여기서 고른 프로젝트가 곧 WBS·Agile·간트·RACI·RAID·Dashboard가 보는 프로젝트입니다.
각 화면 왼쪽 위의 셀렉트는 같은 값을 가리키는 창구가 여럿일 뿐입니다.
그래서 탭을 옮겨도 선택이 첫 프로젝트로 되돌아가지 않습니다.

선택한 프로젝트를 **삭제하면 선택이 자동으로 비워집니다** — 없는 프로젝트를 가리킨 채로
다른 화면에 들어가면 그 화면이 빈 채로 오류를 내기 때문입니다.

### 저장이 거부되면

대화상자가 **닫히지 않고** 그 안에 이유가 뜹니다. 입력값도 그대로 남습니다.
화면 본문에 오류를 적으면 대화상자 뒤에 가려서 "조용히 실패한 것처럼" 보이기 때문에,
저장 성공 여부를 대화상자가 직접 말하도록 되어 있습니다.

## 2.2 프로젝트 삭제가 함께 지우는 것

삭제는 **되돌릴 수 없고, 확인창 한 번이 전부**입니다. 프로젝트에 딸린 모든 것이 데이터베이스
연쇄 삭제(`ON DELETE CASCADE`)로 함께 사라집니다.

| 함께 지워지는 것 | 비고 |
|---|---|
| WBS 항목 전체 | 하위까지 |
| 선후행 관계 | |
| 프로젝트 구성원 | |
| RACI 배정 | |
| RAID 항목과 그 연결 | |
| Backlog 항목 전체 | 보관된 것 포함 |
| Sprint와 Sprint 배정 이력 | **종료된 Sprint의 실적도** |
| 승인 체크포인트 | 승인 기록 포함 |
| 승인된 기준선(Baseline)과 그 항목 스냅샷 | |
| 보고 스냅샷 | |
| 변경 이력(`change_logs`) | |

> **WBS 화면의 "연결 Backlog가 있으면 삭제 거부" 같은 안전장치가 여기에는 없습니다.**
> WBS 항목 하나를 지울 때는 실행 기록이 딸려 나가는 것을 막지만, 프로젝트 삭제는
> "이 프로젝트를 통째로 없앤다"는 뜻이므로 막을 이유가 없습니다. 대신 그만큼 되돌릴 수도
> 없으니, **지우기 전에 [전체 JSON으로 내보내 두세요](#9-내보내기와-가져오기).**

## 2.3 주의할 점

- **프로젝트 상태는 표시용입니다.** "완료"로 바꿔도 지연 판정이 멈추거나 Sprint가 닫히거나
  진척 계산이 얼어붙지 않습니다. 상태에 따른 규칙(요구사항 4.3)은 아직 구현되지 않았습니다.
- **프로젝트 이름에 유일성 제약이 없습니다.** 같은 이름을 두 번 만들 수 있고, 그러면 모든 화면의
  프로젝트 셀렉트에서 구분할 수 없습니다. 가져오기만은 이 사정을 알고 `(가져옴)`을 붙입니다.
- **동시 편집은 마지막 저장이 이깁니다.** 두 사람이 같은 프로젝트를 고쳐도 경고가 없습니다.
- **삭제 확인창에 무엇이 함께 지워지는지 적혀 있지 않습니다.** `"이름" 프로젝트를 삭제할까요?`
  한 줄뿐이므로, 위 표를 기억해 두는 쪽이 안전합니다.
