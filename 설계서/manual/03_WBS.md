# 3. WBS

> 한 줄 요약: 프로젝트의 **범위**를 계층으로 정의하고, 그 계층을 다른 모든 화면이 쓸 수 있는 뼈대로
> 만드는 화면입니다. 여기서 만든 항목이 간트의 막대, Backlog의 귀속 대상, RACI의 행, RAID의 연결
> 대상, 진척 집계의 단위가 됩니다.

---

## 3.1 화면 구성

### 화면 위쪽

| 요소 | 설명 |
|---|---|
| **＋ 파일에서 가져오기** | 오른쪽 위, 최상위 항목 추가 왼쪽. Excel(.xlsx/.xls)·CSV 파일로 여러 항목을 한 번에 붙입니다 → [파일에서 가져오기](#파일에서-가져오기-excel-csv) |
| **＋ 최상위 항목 추가** | 오른쪽 위 버튼. 맨 위 단계를 만듭니다. **등록된 프로젝트가 하나도 없으면 아예 나타나지 않습니다**(파일 가져오기 버튼도 함께 사라집니다) |
| **프로젝트 안내문** | 프로젝트가 없을 때만 뜹니다 — "먼저 프로젝트를 등록해야 WBS를 작성할 수 있습니다"와 프로젝트 화면 링크. WBS는 프로젝트에 속하므로 빈 상태로 시작할 수 없습니다 |
| **프로젝트 셀렉트** | 어떤 프로젝트의 WBS인지 고릅니다. 이 선택은 **모든 화면이 공유**하므로, 여기서 바꾸면 간트·RACI·RAID도 같은 프로젝트를 봅니다 |
| **지연 배너** | 지연이나 지연 위험인 업무가 하나라도 있을 때만 나타납니다 |

**지연 배너**는 이렇게 읽습니다.

```
지연 업무 3건 · 지연 위험 1건        기준일 2026-09-09        간트에서 보기
```

- 숫자는 **leaf(하위가 없는 행)만** 셉니다. Summary는 하위의 지연을 이미 반영하고 있어서 함께 세면
  같은 지연이 레벨 수만큼 중복 집계됩니다. 배너 문구에 "업무"를 붙여 둔 것이 그 신호입니다 —
  표의 배지 개수와 배너 숫자가 다를 수 있는 이유이기도 합니다(배지는 Summary 행에도 붙습니다).
- **기준일은 서버가 정해 내려준 값**입니다. 브라우저 시계가 아니므로, 탭을 오래 열어 둬도 배지와
  기준일이 어긋나지 않습니다.
- **간트에서 보기**는 `/gantt`로 이동합니다. WBS는 구조를 다루는 화면이라 상태는 요약만 보여주고,
  전체 상태(정상·완료·시작 전까지)는 간트에서 봅니다.

### 표 열

| 열 | 무엇이 들어 있나 |
|---|---|
| **WBS** | `1`, `1.2`, `1.2.1` 같은 코드. **자동으로 매겨지며 직접 입력할 수 없습니다.** 항목을 옮기거나 순서를 바꾸면 다시 계산됩니다 |
| **업무명** | 접기/펼치기 토글 → 업무명 → 지연 배지 → 설명(있으면). 계층 깊이만큼 들여쓰기되고, **하위가 있는 행은 굵게** 표시됩니다 |
| **시작일** | 날짜. 값이 없으면 `-` |
| **종료일** | 날짜. 값이 없으면 `-` |
| **실행 방식** | 하위가 있으면 하위 Work Package들의 **요약**, 없으면 그 항목 자신의 값 |
| **연결 Backlog** | 이 가지에 붙어 있는 Backlog 항목 수 |
| **진척** | 공통 집계가 계산한 값 (막대 + % + 근거) |
| **(작업)** | `하위` · `수정` · `삭제` 버튼 |

표는 셀을 줄바꿈하지 않고 **가로로 스크롤**합니다. 설명 칸만 폭 상한이 있어 잘리고, 마우스를 올리면
전체가 뜹니다.

### 업무명 칸의 표시들

- **▼ / ▶ 토글** — 하위가 있는 행에만 나타납니다. 접어도 그 아래의 지연 배지는 볼 수 없게 되지만,
  **접힌 Summary 자신에게 배지가 붙기 때문에** 안쪽 지연을 놓치지 않습니다.
- **지연 배지** — `지연 12일` (빨강) 또는 `지연 위험` (주황). **이 두 가지만 표시합니다.** 정상·완료·
  시작 전까지 모두 배지를 달면 구조를 읽는 데 방해가 되기 때문입니다. 마우스를 올리면 근거가 뜹니다
  (예: `기대 진행률 60%, 실제 30% (30%p 부족)`).
- **설명** — 흐린 작은 글씨로 이름 뒤에 붙습니다.

### 실행 방식 칸

| 상황 | 표시 |
|---|---|
| 하위가 있음 | `Waterfall 2 · Agile 3 · 미지정 1` — **손자까지 포함한** 하위 Work Package를 모드별로 셉니다. 0건인 모드는 빼고, **`미지정`은 숨기지 않습니다**(배정되지 않은 Work Package가 확인 대상이므로). 셀 것이 없으면 `-` |
| 하위가 있고, 자신도 예전 실행 방식을 갖고 있음 | 요약 뒤에 점선 칩으로 `보관 Agile`. "지금 적용되는 값이 아니다"를 알리는 표시입니다 |
| 하위가 없음 | 자기 값(`Waterfall` / `Agile` / `Hybrid`), 또는 흐린 `미지정` |

### 연결 Backlog 칸

`8개 항목 / 4개 완료 · 보관 2` 형태입니다. 보관은 따로 적습니다 — 열린 일은 아니지만 완전히 숨기면
비어 있는 Work Package처럼 보이기 때문입니다.

- **Work Package 행의 숫자만 링크**입니다. 누르면 그 Work Package로 필터링된 Backlog 화면으로
  갑니다.
- **상위 행의 숫자는 하위 전체의 합계**라 갈 곳이 하나가 아니므로 글자만 보여줍니다.
- 이 가지에 Backlog가 하나도 없으면 `-`.

### 진척 칸

`▬▬▬░░ 62% 가중 집계 불완전 인수 대기` 처럼 최대 네 조각이 나옵니다.

| 조각 | 뜻 |
|---|---|
| 막대 + % | 공통 집계가 계산한 값. **`산정 전`이면 막대를 그리지 않습니다** — 0%와 구별해야 하기 때문입니다 |
| 근거 라벨 | `Agile` / `Waterfall` / `Hybrid` / `가중 집계` / `하위 평균` / `산정 전`. **`수동 입력`일 때만 라벨을 생략**합니다(예전과 같은 계산이라 굳이 알릴 것이 없음) |
| `불완전` | 하위 일부가 산정 전이거나 가중치가 없어 평균에서 빠졌다는 표시 |
| `인수 대기` | 실행이 100%인데 인수 상태가 `인수 대기`로 남아 있다는 표시. 진척과 인수는 별개입니다 |

막대에 마우스를 올리면 왜 이 숫자인지 한 줄로 뜹니다 (산정 전이면 그 사유, 아니면 근거 설명).

### 표 아래

- **최상위 드롭존** — `여기로 끌어다 놓으면 최상위 항목이 됩니다`. 드래그 중 이 위로 가면 강조됩니다.
- **안내 문구** — 드래그 규칙 요약.
- **항목이 하나도 없을 때** — `등록된 WBS 항목이 없습니다. 위 ＋ 최상위 항목 추가로 첫 항목을
  만들어 보세요.`

### 다른 화면에서 넘어왔을 때

Backlog·간트·Dashboard의 링크로 들어오면(주소에 `?focus=...`가 붙습니다) 그 행의 **조상이 모두
펼쳐지고**, 화면이 그 행으로 스크롤되며, **약 4초간 배경이 강조**됩니다. 강조는 스스로 사라집니다 —
계속 남아 있으면 "선택된 행"처럼 읽히는데, 이 화면에 선택이라는 개념은 없기 때문입니다. 주소의
`focus`는 곧바로 지워지므로 새로고침해도 다시 튀지 않습니다.

## 3.2 기본 작업

### 항목 만들기

**최상위 항목**

1. 오른쪽 위 **＋ 최상위 항목 추가**를 누릅니다.
2. 대화상자 제목이 `최상위 항목 추가`인지 확인합니다.
3. **업무명**을 넣습니다(필수). 나머지는 나중에 채워도 됩니다.
4. **추가**.

**하위 항목**

1. 부모가 될 행의 **하위** 버튼을 누릅니다.
2. 대화상자 제목이 `하위 항목 추가 — 1.2 화면 설계`처럼 부모를 밝힙니다.
3. **업무명**을 넣고 **추가**.

새 항목은 **구분이 `Work Package`로 시작**합니다. 방금 만든 항목에는 자식이 없으니 그것이 맞는
출발점이고, 하위를 두려면 나중에 명시적으로 `Summary`로 바꿉니다(→ [3.4](#34-이-화면의-규칙)).

새 항목은 **같은 부모의 맨 끝에 붙습니다.** 위치를 바꾸려면 만든 뒤 드래그합니다.

### 파일에서 가져오기 (Excel · CSV)

이미 Excel이나 CSV로 정리해 둔 WBS 표가 있다면, 한 항목씩 만드는 대신 파일로 한 번에 넣을 수
있습니다. 항목을 하나씩 폼에 적는 화면 자체는 그대로 두고, **여러 행을 만드는 또 다른 입구**를
더한 것입니다.

1. **＋ 파일에서 가져오기** → 대화상자가 열립니다.
2. **파일**을 고릅니다. `.csv`, `.xlsx`, `.xls`를 받습니다.
3. **상위 항목**을 고릅니다. `(최상위)` 또는 이미 있는 **Summary** 항목 중 하나입니다 — Work
   Package는 목록에 나오지 않습니다(하위를 둘 수 없는 것은 한 항목씩 추가할 때와 같습니다).
4. **가져오기**.

**열 순서는 고정**입니다: **레벨 · 업무명 · 시작일 · 종료일 · 진행률**. 대화상자의
**`양식 CSV 내려받기`**를 누르면 이 순서로 된 예시 파일을 받아, 값만 채워 다시 올릴 수 있습니다.

| 열 | 필수 | 설명 |
|---|---|---|
| **레벨** | ✔ | `1`부터 시작하는 **들여쓰기 단계**입니다. WBS 코드(`1.2.1`)가 아닙니다. 직전 행보다 **한 단계씩만** 깊어질 수 있습니다 |
| **업무명** | ✔ | 비어 있으면 그 행이 거부됩니다 |
| **시작일 · 종료일** | | `2026-09-10` 형식. 비워 둘 수 있습니다(일정 미정으로 들어갑니다) |
| **진행률** | | 0~100. **비우면 0으로 들어갑니다** |

- **첫 행은 항상 머리글로 보고 건너뜁니다.** 무엇이 적혀 있든 상관없습니다.
- **구분(Summary/Work Package)은 파일에 적지 않습니다.** 바로 다음 행이 한 단계 더 깊으면
  Summary, 아니면 Work Package로 **자동으로 정해집니다** — WBS 화면에서 손으로 만들 때 새
  항목이 항상 Work Package로 시작하는 것과 같은 규칙이고, 파일에서도 자식이 생기는 순간
  Summary가 됩니다.
- **실행 방식·가중치·인수 상태는 이 파일로 받지 않습니다.** 이미 갖고 있는 평범한 WBS 표를
  그대로 올릴 수 있게 하려는 것이고, 이 값들은 가져온 뒤 이 화면에서 각 항목을 **수정**해
  채웁니다.
- **골라 둔 상위 항목의 맨 끝 하위로 붙습니다.** 기존 항목은 건드리지 않습니다 — 형제 순서도,
  다른 가지의 코드도 영향받지 않습니다.

**행 하나라도 문제가 있으면 파일 전체가 거부되고 아무것도 만들어지지 않습니다.** 대화상자 안에
문제 행이 전부 나열됩니다.

```
3행: 레벨이 1에서 3(으)로 두 단계 이상 깊어질 수 없습니다. 한 단계씩만 들어갈 수 있습니다.
4행: 업무명이 비어 있습니다.
```

행 번호는 **파일에서 실제로 보이는 줄 번호**입니다(머리글을 1행으로 셉니다) — Excel에서 그 행을
바로 찾아 고칠 수 있습니다. 고친 뒤 같은 파일을 다시 올리면 됩니다.

### 수정

1. 행의 **수정** 버튼.
2. 대화상자 제목이 `항목 수정 — 1.2 화면 설계`로 뜨고 현재 값이 채워집니다.
3. 고치고 **저장**.

**저장이 거부되면 대화상자가 닫히지 않고 그 안에 사유가 표시됩니다.** 입력한 값은 그대로 남으니
다시 칠 필요가 없습니다. 성공했을 때만 닫힙니다.

### 이동 — 드래그

**모든 행을 끌 수 있습니다.** 놓는 위치에 따라 뜻이 달라집니다.

| 놓는 곳 | 결과 | 화면 표시 |
|---|---|---|
| 행의 **위쪽 가장자리**(위 25%) | 그 행 **바로 앞**으로. 계층은 그 행과 같아집니다 | 행 위에 강조선 |
| 행의 **아래쪽 가장자리**(아래 25%) | 그 행 **바로 뒤**로. 계층은 그 행과 같아집니다 | 행 아래에 강조선 |
| 행의 **가운데**(가운데 50%) | 그 행의 **하위**가 됩니다(맨 앞에 들어갑니다) | 행 전체가 강조 |
| 표 아래 **드롭존** | **최상위**로 올라옵니다(맨 앞) | 드롭존이 강조 |

끌고 있는 행은 반투명해집니다. **놓을 수 없는 자리에서는 아무 표시도 나타나지 않고 놓아도
아무 일도 일어나지 않습니다** — 어떤 자리가 금지인지는 [3.4](#34-이-화면의-규칙)에 있습니다.

이동하면 **WBS 코드가 즉시 다시 계산**됩니다. 옮긴 항목뿐 아니라 그 뒤의 형제, 다른 가지의 코드까지
바뀔 수 있습니다.

### 삭제

1. 행의 **삭제** 버튼.
2. 브라우저 확인창이 뜹니다: `"1.2 화면 설계" 항목을 삭제할까요?`
   하위가 있으면 한 줄이 더 붙습니다: `하위 항목도 모두 함께 삭제됩니다.`
3. 확인하면 **그 항목과 그 아래 전부**가 사라집니다.

거부될 수 있습니다(살아 있는 Backlog가 붙은 경우). 이때 사유는 **표 위 붉은 글씨**로 나옵니다 —
대화상자가 없는 경로라서입니다.

## 3.3 입력 필드 하나하나

편집 대화상자에는 열 개의 필드가 있습니다. 추가 대화상자와 수정 대화상자는 **같은 폼**입니다.

| 필드 | 무엇을 넣나 | 비우면 | 어디에 영향을 주나 |
|---|---|---|---|
| **업무명** | 이 업무의 이름 (**필수**) | 저장 버튼을 눌러도 아무 일도 일어나지 않습니다(공백만 있는 경우 포함) | 표·간트 막대 레이블·RACI 행 머리·Backlog의 귀속 표시·RAID의 연결 대상 이름 |
| **설명** | 한 줄 메모 (선택) | 업무명 뒤에 아무것도 붙지 않습니다 | 표의 흐린 보조 글씨, CSV 내보내기 |
| **시작일** | 계획 시작일 | 지연 판정이 `일정 미정`이 되고 배지가 사라집니다. 간트에 막대가 그려지지 않고, 선후행 제약에도 참여하지 않습니다 | 지연 판정, 간트, 임계 경로, 일정 재계산 |
| **종료일** | 계획 종료일(**당일 포함**) | 위와 같습니다 | 위와 같음 |
| **진행률 (%)** | 0~100 정수 | **비우면 0으로 저장됩니다**(값을 지운 것이 아니라 0을 넣은 것이 됩니다) | 지연 판정. 진척 칸에는 **실행 방식이 미지정일 때만** 그대로 나타납니다 |
| **구분** | `Work Package` 또는 `Summary` | (셀렉트라 빈 값이 없습니다) | 하위를 둘 수 있는지, 실행 방식을 가질 수 있는지, Backlog를 붙일 수 있는지 |
| **실행 방식** | `미지정` / `Waterfall` / `Agile` / `Hybrid` | `미지정`이면 진척이 **입력한 진행률 그대로**(`수동 입력`)가 됩니다 | 진척 계산식, 상위 행의 실행 방식 요약, Dashboard의 "데이터 누락" 카드 |
| **가중치** | 0 이상 정수. **같은 부모 아래 형제 사이의 비중** | **"정하지 않음"이고 0이 아닙니다.** 형제 중 아무도 가중치가 없으면 그 가지는 예전처럼 하위 개수 평균(`하위 평균`)으로 집계됩니다. **형제 중 누군가는 넣고 나만 비우면 나는 평균에서 빠지고 부모에 `불완전`이 붙습니다** | 상위(Summary)의 진척 |
| **Hybrid 비중 α (%)** | 0~100. Agile 요소가 차지하는 비율(나머지가 승인 요소) | Hybrid인데 비워 두면 그 항목은 **`산정 전`**이 됩니다. 폼이 그 자리에서 경고합니다 | Hybrid Work Package의 진척 |
| **인수 상태** | `해당 없음` / `인수 대기` / `인수 완료` | `해당 없음` = 인수 절차가 없는 업무 | 진척과 **직교**합니다. 실행 100% + `인수 대기` = 진척 칸의 `인수 대기` 칩, Dashboard의 "인수 대기" 카드 |

### 비활성이 되는 칸

| 칸 | 언제 비활성 | 왜 |
|---|---|---|
| **시작일 · 종료일 · 진행률** | **하위가 있는 항목**을 수정할 때 | 이 세 값은 하위에서 집계됩니다. 여기서 고쳐도 화면에는 계산값이 보이므로, 입력받는 시늉만 하는 것보다 막는 편이 정직합니다 |
| **실행 방식** | 구분이 `Summary`일 때 | 실행 방식은 최하위 Work Package의 성질입니다. Summary는 하위의 것을 요약만 합니다 |
| **Hybrid 비중 α** | 실행 방식이 `Hybrid`가 아닐 때 | 다른 방식에서는 쓰이지 않는 값입니다 |
| **구분의 `Work Package` 선택지** | 하위가 있는 항목을 수정할 때 | 하위가 있는 항목은 최하위 관리 단위일 수 없습니다 |

### 폼이 그 자리에서 알려주는 것

- **가중치 안내**(항상): `가중치를 비워 두면 이 가지는 예전처럼 하위 평균으로 집계됩니다. 0은
  "진척에 기여하지 않음"이라 미입력과 다릅니다.`
- **Hybrid에 α가 없을 때**: `Hybrid는 비중(α)이 있어야 진척을 셀 수 있습니다. 비워 두면 산정 전으로
  표시됩니다.`
- **하위가 있는 Summary를 수정할 때**: 일정·진행률이 왜 비활성인지.
- **구분이 Summary일 때**: 실행 방식을 갖지 않는 이유. **보관 중인 값이 있으면** 그 값과 함께
  "구분을 Work Package로 되돌리면 다시 적용됩니다"까지 알려줍니다.
- **하위가 있어 Work Package로 되돌릴 수 없을 때**: `하위 항목을 먼저 옮기거나 삭제하세요.`

대화상자는 열리면 **첫 입력 칸에 포커스**가 가고, `Esc`로 닫히며, `Tab`이 대화상자 밖으로 새지
않습니다.

## 3.4 이 화면의 규칙

거부되는 동작과 그 이유입니다. 대부분은 **화면이 먼저 막고, 서버가 최종 방어선**입니다.

### "하위" 버튼이 비활성입니다

**그 항목이 Work Package이기 때문입니다.** 마우스를 올리면 이유가 뜹니다 —
`Work Package에는 하위 항목을 둘 수 없습니다. 수정에서 구분을 Summary로 바꾸세요.`

Work Package는 **최하위 관리 단위**라는 선언입니다. 여기에 Backlog가 붙고 가중치가 매겨집니다.
자식이 하나 생겼다고 조용히 상위 항목으로 바뀌면, 붙어 있던 실행 방식과 Backlog 귀속이 말없이
고아가 됩니다. 그래서 **구분을 바꾸는 것은 사람이 하는 명시적인 행위**여야 합니다.

같은 이유로, **드래그해서 Work Package 안쪽(행 가운데)에 놓는 것도 불가능**합니다. 위/아래 가장자리에
놓아 형제로 만드는 것은 됩니다 — 그건 그 Work Package의 부모 아래로 들어가는 것이지 그 안으로
들어가는 것이 아니기 때문입니다.

**파일 가져오기의 상위 항목 선택도 같은 규칙을 따릅니다.** 그래서 그 목록에는 Work Package가
아예 나오지 않습니다 — 골라서 거부당하는 것보다 애초에 고를 수 없는 편이 낫기 때문입니다.

### 구분에서 `Work Package`를 고를 수 없습니다

**하위가 있는 항목이기 때문입니다.** 하위를 먼저 다른 곳으로 옮기거나 지워야 합니다.
(서버도 같은 이유로 거부합니다: `하위 항목이 있는 항목은 Work Package로 바꿀 수 없습니다.`)

### `Summary`로 바꾸려는데 거부됩니다

메시지: `연결된 Backlog 항목이 3건 있어 Summary로 바꿀 수 없습니다 (로그인 화면, 목록 화면, … 등).
다른 Work Package로 옮기거나 보관하세요.`

Summary는 **하위를 집계하는 자리**라, 여기에 Story가 직접 붙어 있으면 그 무게가 두 번 셉니다 —
Summary 자신의 집계에서 한 번, 하위 집계에서 또 한 번. 그래서 살아 있는 Backlog가 붙은 Work
Package는 Summary가 될 수 없습니다.

**보관된 Backlog는 막지 않습니다.** 보관은 "이건 접어둔다"는 명시적인 표시이기 때문입니다.

### 실행 방식 셀렉트가 비활성입니다

**구분이 Summary이기 때문입니다.** 실행 방식은 최하위 Work Package에 지정합니다.

이때 **이전에 지정했던 값은 지워지지 않고 보관**됩니다. 표에 `보관 Agile` 칩으로 보이고, 구분을
Work Package로 되돌리면 그대로 살아납니다. 그래서 이 규칙은 *"Summary는 실행 방식이 null이어야
한다"*가 아니라 *"Summary의 실행 방식은 바꿀 수 없다"*로 되어 있습니다 — 폼이 보관값을 그대로
돌려보내도 통과해야 하기 때문입니다.

### 드래그해도 놓이지 않습니다

- **자기 자신 위에** — 무의미합니다.
- **자기 하위 어딘가에** — 순환이 됩니다. 위/아래 가장자리도 마찬가지로 막힙니다(그 자리의 새 부모가
  결국 자기 자신의 하위이기 때문입니다).
- **Work Package 안쪽에** — 위 규칙.

서버도 같은 것들을 거부합니다: `항목을 자기 자신의 하위로 이동할 수 없습니다.` /
`항목을 자신의 하위 항목 아래로 이동할 수 없습니다.`

### 삭제가 거부됩니다

메시지: `연결된 Backlog 항목이 2건 있어 삭제할 수 없습니다 (…). 다른 Work Package로 옮기거나
보관하세요.`

**삭제 대상은 그 항목 하나가 아니라 그 아래 전부**입니다. 판정도 그 범위 전체를 보고 합니다 —
지우려는 단계 어딘가에 살아 있는 Backlog가 하나라도 있으면 거부됩니다.

이 가드가 없으면 상위 하나를 지우는 것으로 실행 기록이 조용히 사라집니다. **보관된 항목만
남았다면** 사유를 남기고 연결을 끊은 뒤 삭제가 진행됩니다.

### 값의 범위

| 필드 | 허용 범위 | 벗어나면 |
|---|---|---|
| 진행률 | 0~100 | 400 오류 |
| 가중치 | 0 이상 | 400 오류 |
| Hybrid α | 0~100 | 400 오류 |
| 업무명 | 공백만이면 안 됨 | 폼이 제출 자체를 하지 않습니다 |

### 왜 저장하면 표 전체가 다시 그려지나

**변경 API가 매번 트리 전체를 돌려주기 때문입니다.** 항목 하나를 옮기면 다른 행의 WBS 코드,
상위의 일정·진척·실행 방식 요약이 함께 바뀝니다. 바뀐 행만 돌려주면 화면이 낡은 코드를 계속
보여주게 됩니다.

## 3.5 다른 화면과의 관계

### 여기서 한 일이 어디로 가나

| WBS에서 한 일 | 어디가 바뀌나 |
|---|---|
| 항목 추가·이름 변경 | 간트에 행이 생기고, RACI에 행이 생기고, Backlog의 "귀속 Work Package" 목록과 RAID의 "연결 대상" 목록에 나타납니다 |
| 시작일·종료일 변경 | 간트의 현재 계획 막대, 지연 판정, 임계 경로의 여유(float), 일정 재계산의 결과 |
| 진행률 변경 | 지연 판정. 실행 방식이 미지정인 항목이면 진척 숫자까지 |
| 구분을 Work Package로 지정 | Backlog를 붙일 수 있는 대상이 됩니다. 진척 탭에서 승인 체크포인트를 넣을 수 있는 행이 됩니다 |
| 실행 방식 지정 | 진척 계산식이 바뀝니다. Dashboard의 "실행 방식 분포"와 "데이터 누락"이 움직입니다 |
| 가중치 입력 | 그 항목의 부모 진척이 `하위 평균`에서 `가중 집계`로 바뀝니다. 프로젝트 전체 진척도 함께 |
| 순서·계층 변경 | **모든 화면의 WBS 코드**. 간트 행 순서, RACI 행 순서, CSV 내보내기 |
| 삭제 | 아래 표 참조 |

### 항목을 지우면 함께 사라지는 것 / 남는 것

| 대상 | 결과 |
|---|---|
| **하위 WBS 항목** | 전부 함께 삭제 |
| **선후행 관계** | 그 항목이 걸린 관계는 함께 삭제 |
| **RACI 배정** | 함께 삭제 |
| **승인 체크포인트** | 함께 삭제 |
| **Backlog 항목** | **삭제되지 않습니다.** 살아 있으면 삭제 자체가 거부되고, 보관된 것만 있으면 연결만 끊긴 채 남습니다 |
| **RAID 항목** | **삭제되지 않습니다.** 연결만 끊깁니다 — 계획이 사라진다고 위험 기록까지 사라지면 안 됩니다 |
| **승인된 기준선(Baseline)의 기록** | **남습니다.** "그때는 이런 범위였다"가 지금 범위가 바뀌었다고 없어지면 안 되기 때문입니다 |

### 다른 화면에서 여기로 들어오는 길

- **Backlog** 행의 귀속 Work Package 링크 → 그 WBS 행으로.
- **간트**의 "기준 종료일 초과" 목록 링크 → 그 WBS 행으로.
- **Dashboard**의 지연 업무·데이터 누락 카드 링크 → 그 WBS 행으로.

모두 그 행의 조상을 펼치고 스크롤한 뒤 잠깐 강조합니다.

### 캐시 — "저장했는데 다른 화면 숫자가 그대로예요"

WBS를 고치면 내부 리비전이 올라가고, **간트·Dashboard는 다음에 그 화면에 들어갈 때 다시 읽습니다.**
반대로 **간트에서 선후행 관계를 추가·삭제해도 WBS는 다시 읽지 않습니다** — 선후행은 WBS 트리에
없는 정보라 트리가 낡을 이유가 없기 때문입니다. 단 **간트의 일정 재계산은 WBS 날짜를 바꾸므로**
WBS도 다시 읽습니다.

Backlog를 고쳐도 WBS는 다시 읽습니다 — 트리가 연결 Backlog 수를 싣고 있기 때문입니다.

## 3.6 실무 예시

### 예시 1 — 새 프로젝트의 뼈대를 세운다

*"차세대 포털 구축"의 WBS를 3단계로 잡고 싶다.*

목표하는 모습:

```
1  요구 분석            (Summary)
   1.1  현행 조사       (Work Package · Waterfall)
   1.2  요구사항 정의   (Work Package · Waterfall)
2  설계·개발            (Summary)
   2.1  화면 설계       (Work Package · Hybrid, α 40)
   2.2  API 개발        (Work Package · Agile)
```

**순서가 중요합니다.**

1. **＋ 최상위 항목 추가** → 업무명 `요구 분석` → **추가**. 새 항목이라 구분은 `Work Package`입니다.
2. 방금 만든 `1 요구 분석` 행의 **하위** 버튼을 누르려니 **비활성**입니다.
   → **수정**을 눌러 **구분을 `Summary`로 바꾸고 저장**합니다.
3. 이제 **하위** 버튼이 살아납니다. `1.1 현행 조사`, `1.2 요구사항 정의`를 차례로 추가합니다.
4. 각 하위를 **수정**해서 **실행 방식 `Waterfall`**, 시작일·종료일을 넣습니다.
5. `2 설계·개발`도 같은 순서로 만듭니다. `2.1 화면 설계`는 실행 방식을 `Hybrid`로 고른 뒤
   **Hybrid 비중 α에 40**을 넣습니다 — 비우면 그 행이 `산정 전`이 됩니다.

> **함정** — 새 항목을 만들 때 **실행 방식을 먼저 고르고 나서 구분을 `Summary`로 바꾸면 추가가
> 거부**됩니다(실행 방식 셀렉트가 비활성이라 되돌릴 수도 없습니다). 구분을 `Summary`로 바꿀
> 계획이라면 실행 방식은 `미지정`으로 둔 채 만드세요. 이미 그 상태가 됐다면 구분을 잠시
> `Work Package`로 되돌려 실행 방식을 `미지정`으로 바꾼 뒤 다시 `Summary`로 고칩니다.

**확인**: `1 요구 분석` 행의 실행 방식 칸이 `Waterfall 2`로, `2 설계·개발` 행이 `Agile 1 · Hybrid 1`로
보이면 제대로 된 것입니다.

### 예시 2 — 이미 만들어 둔 Work Package를 쪼개고 싶다

*`2.2 API 개발`이 너무 커서 `인증 API`와 `주문 API`로 나누려 한다. 그런데 `2.2`에는 이미 Story가
5건 붙어 있다.*

1. `2.2 API 개발`의 **하위** 버튼 → 비활성입니다(Work Package라서).
2. **수정** → 구분을 `Summary`로 → **저장** → **거부됩니다**:
   `연결된 Backlog 항목이 5건 있어 Summary로 바꿀 수 없습니다 (…). 다른 Work Package로 옮기거나
   보관하세요.`
3. 먼저 **하위 두 개를 만들 자리를 확보**합니다. 하지만 2번이 막혀 있으니 순서를 바꿉니다.
   - `2 설계·개발` 아래에 **하위** 버튼으로 `인증 API`, `주문 API`를 새로 만듭니다
     (`2.3`, `2.4`가 됩니다).
   - **Backlog 화면**으로 가서 5건의 귀속 Work Package를 `2.3` 또는 `2.4`로 옮깁니다.
     (Epic이나 Story의 하위 Task는 상위에서 상속되므로 상위만 옮기면 따라옵니다.)
4. 이제 `2.2 API 개발`을 **수정** → 구분 `Summary` → **저장** (통과합니다).
5. `2.3`, `2.4` 행을 각각 `2.2` 행의 **가운데**로 드래그해 하위로 넣습니다.
   → 코드가 `2.2.1`, `2.2.2`로 다시 매겨집니다.

**왜 이렇게 도는가**: Summary는 하위를 집계하는 자리라 Story를 직접 붙들고 있을 수 없고, 시스템은
"어느 하위로 옮길지"를 대신 정해 주지 않기 때문입니다.

### 예시 3 — 단계 하나를 통째로 지우려는데 거부된다

*`3 파일럿` 단계를 없애기로 했다.*

1. `3 파일럿` 행의 **삭제** → 확인창에 `하위 항목도 모두 함께 삭제됩니다.`가 붙습니다 → 확인.
2. 표 위에 붉은 글씨: `연결된 Backlog 항목이 2건 있어 삭제할 수 없습니다 (파일럿 배포 스크립트,
   파일럿 피드백 반영). 다른 Work Package로 옮기거나 보관하세요.`
3. 두 건을 어떻게 할지 정합니다.
   - **일이 살아 있다** → Backlog 화면에서 다른 Work Package로 귀속을 옮깁니다.
   - **끝났거나 접는다** → Backlog 화면에서 **보관**합니다. (진행 중인 Sprint에 배정돼 있으면
     보관도 거부되니, Sprint에서 먼저 제거해야 합니다.)
4. 다시 삭제하면 진행됩니다. 이때 **RAID 항목은 지워지지 않고 연결만 끊깁니다** — RAID 화면에서
   그 항목의 연결 대상이 `(없음)`으로 바뀝니다.

**대안**: 정말 지우기보다 그 가지의 계획을 남겨 두고 싶다면, 삭제 대신 **최상위 드롭존으로 끌어내려**
다른 단계 밖으로 빼 두는 방법도 있습니다. 코드만 뒤로 밀릴 뿐 기록은 그대로 남습니다.

### 예시 4 — 이미 있는 Excel 계획표를 그대로 올린다

*컨설팅사에서 받은 Excel WBS가 있고, 들여쓰기로 단계를 표현해 두었다.*

```
레벨  업무명           시작일        종료일        진행률
1     요구 분석
2       현행 조사       2026-01-05   2026-01-12
2       요구사항 정의   2026-01-13   2026-01-30
1     설계
```

1. 이 표를 **레벨·업무명·시작일·종료일·진행률** 순서의 CSV(또는 xlsx)로 정리합니다. 진행률
   칸은 비워 둡니다 — 아직 아무도 시작 안 했습니다.
2. **＋ 파일에서 가져오기** → 파일 선택 → **상위 항목은 `(최상위)`** (이미 있는 프로젝트의
   맨 위 단계로 붙일 것이므로) → **가져오기**.
3. 결과: `1 요구 분석`(Summary, 바로 다음 행이 한 단계 깊으므로), 그 아래 `1.1 현행 조사`·
   `1.2 요구사항 정의`(둘 다 진행률 0), 그리고 `2 설계`(Work Package, 하위가 없으므로)가
   기존 항목들 뒤에 새 최상위로 붙습니다.
4. **각 Work Package를 수정**해 실행 방식을 지정합니다 — 파일은 이름·기간·진행률만 옮겼을 뿐,
   Agile/Waterfall 여부는 이 화면에서 사람이 정합니다.

**같은 파일을 이미 있는 `2 설계·개발`(Summary) 아래에 끼워 넣고 싶다면**, 3번에서 **상위 항목을
`2 설계·개발`로** 고르기만 하면 됩니다 — 나머지는 같습니다.

## 3.7 주의할 점

### 수정하면 실적·예상 종료가 지워집니다

**가장 조심해야 할 것입니다.** WBS 항목에는 실제 시작일·실제 완료일·예상 종료일이 저장될 수 있고
간트가 그것을 그리지만, **이 편집 폼에는 그 세 칸이 없습니다.** 그래서 이 화면에서 항목을
**수정·저장하면 그 값들이 비워집니다.**

- 지금 그 값이 들어 있는 경우는 **가져오기(JSON)로 들여온 프로젝트**뿐입니다.
- 가져온 프로젝트의 실적을 보존해야 한다면 **그 항목을 이 화면에서 수정하지 마세요.**
- 꼭 고쳐야 한다면 **먼저 프로젝트를 JSON으로 내보내 두세요.**

### 파일로 가져온 항목도 실행 방식·가중치는 비어 있습니다

파일 가져오기는 업무명·시작일·종료일·진행률만 받습니다. 그래서 가져온 직후에는 모든 항목이
**실행 방식 미지정**이고 **진척은 입력한 진행률 그대로**(`수동 입력`)입니다. Agile·Waterfall·
Hybrid로 계산하고 싶다면 항목마다 **수정**을 열어 실행 방식을 지정하세요.

### 지연 배지와 진척 숫자는 서로 다른 값을 봅니다

한 행에서 **진척 칸은 `Agile 100%`인데 배지는 `지연`** 일 수 있습니다. 모순이 아니라, 두 표시가
다른 값을 보기 때문입니다.

| 표시 | 근거 |
|---|---|
| **진척 칸** | 공통 집계 결과(완료 Story 비율, 승인된 체크포인트 비율 등) |
| **지연 배지** | 편집 폼에 **직접 입력한 진행률** |

실행 방식이 `미지정`인 항목에서는 둘이 같은 값이라 차이가 없습니다. **Agile·Waterfall·Hybrid로
전환한 항목에서만** 갈라집니다. 지연 배지를 실제와 맞추려면 진행률 칸도 함께 갱신해야 합니다.

### 하위가 있는 항목을 저장하면 집계된 일정이 자기 값이 됩니다

시작일·종료일·진행률 칸이 비활성이어도 **화면에 보이는 집계값이 그대로 저장됩니다.** 평소에는
표시가 달라지지 않지만(어차피 하위에서 다시 계산하므로), 나중에 **그 항목의 하위를 전부 지우면**
그때 복사된 값이 그 항목 자신의 일정으로 남습니다. 원래 넣어 뒀던 값이 아닐 수 있으니 확인하세요.

### WBS 코드는 언제든 바뀝니다

`1.2.1`은 **트리에서의 위치**일 뿐이라, 앞의 형제를 하나 추가하거나 지우면 달라집니다.
**회의록·이메일에 코드를 박아 두지 마세요.** 코드는 "지금 화면에서 찾는 법"이고, 항목의 정체성은
이름입니다.

### `산정 전`은 0%가 아닙니다

막대가 없고 `산정 전`이라고 적힌 것은 **아직 셀 근거가 없다**는 뜻입니다. 착수 전 프로젝트가
"0% 진행"으로 보이지 않게 하려는 구분입니다. 흔한 원인:

- Agile인데 집계 대상 Story·Bug가 없다
- Waterfall인데 승인 체크포인트가 없다
- Hybrid인데 α가 비어 있다
- 하위가 없는 Summary다 (전환은 했는데 아직 자식을 안 만든 상태)

### 가중치를 비우는 것과 0은 다릅니다

- **비움** = "아직 안 정했다". 형제 중 아무도 안 정했으면 예전 방식(하위 개수 평균)이 유지됩니다.
- **0** = "이 가지는 진척에 기여하지 않는다".
- **형제 중 일부만 넣으면** 안 넣은 쪽이 평균에서 빠지고 부모에 `불완전`이 붙습니다. **넣으려면
  형제 전체에 넣으세요.**

### 배너 숫자와 배지 개수가 다릅니다

배너는 **leaf만** 세고, 배지는 **Summary 행에도 붙습니다.** 지연된 leaf 하나가 3단계 아래에 있으면
배지는 네 개(자신 + 조상 3), 배너는 1건입니다. 의도된 것입니다 — 접어 둔 상태에서 안쪽 지연을
놓치지 않으려고 배지는 위로 올리고, 건수는 중복되지 않게 leaf로 셉니다.

### 종료일 당일은 아직 지연이 아닙니다

날짜가 **하루 지나야** `지연`이 됩니다. 그리고 **진행률 100%는 종료일이 지났어도 완료**로 봅니다 —
실제 완료일을 이 화면에서 기록할 수 없어 "지연 완료"를 구분할 근거가 없기 때문입니다.

### 영업일 개념이 없습니다

시작일~종료일은 **달력일**이고 주말·공휴일도 그대로 흘러갑니다. 기대 진행률도 달력일 기준의
직선입니다.

### 동시 편집은 마지막 저장이 이깁니다

두 사람이 같은 항목을 열어 두고 각자 저장하면, 나중 저장이 앞의 것을 조용히 덮어씁니다. 경고는
없습니다.
