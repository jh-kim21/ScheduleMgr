# 9. 내보내기와 가져오기

**프로젝트 화면 한 곳에서만** 합니다. 내보내는 단위가 프로젝트이기 때문입니다. 화면마다 버튼을
두면 "전체 JSON"이 여러 벌로 중복되고, 무엇이 내보내지는 단위인지도 흐려집니다.

## 9.1 무엇을 고를 수 있는가

프로젝트 행의 **내보내기** 버튼을 누르면 메뉴가 열립니다.

| 메뉴 | 형식 | 용도 |
|---|---|---|
| **프로젝트 전체** | JSON · 다시 가져올 수 있는 형식 | 프로젝트를 **남에게 넘기기** 위한 것 |
| **WBS** | CSV · Excel에서 열기 | |
| **Backlog** | CSV · Epic·Story·Bug·Task | |
| **RACI** | CSV · 업무 × 구성원 표 | 사람이 **Excel에서 읽기** 위한 것 |
| **RAID** | CSV · 위험·가정·이슈·의존성 | |

### JSON과 CSV는 목적이 반대입니다

| | 전체 JSON | 화면별 CSV |
|---|---|---|
| **읽는 쪽** | 이 앱(가져오기) | 사람(Excel) |
| **값의 표현** | enum 그대로 (`DELAYED`) | 한글 라벨 (`지연`) |
| **판정값** | **넣지 않습니다** | **넣습니다** |
| **만드는 곳** | 서버 | 브라우저 |
| **기준일** | 없음 | 열 머리글에 박혀 있음 |

**JSON에 판정값을 넣지 않는 이유**는 그것들이 전부 "오늘" 또는 "다른 행"을 기준으로 계산되는
값이기 때문입니다. 지연 상태·선후행 위반·여유(float)·노출도·기한 초과가 파일에 박히는 순간
거짓이 됩니다. 예외는 WBS 코드 하나로, 사람이 파일을 읽을 때 필요해서 넣되 파생 값입니다.

**CSV에는 반대로 판정값을 넣습니다.** 그날 화면이 보여 준 것의 스냅샷이기 때문입니다.
그래서 기준일을 열 머리글에 박아 둡니다 — `지연 상태 (기준일 2026-09-07)`,
`기한 초과 (기준일 2026-09-07)`. 며칠 뒤 파일을 열어도 무엇 기준인지 알 수 있습니다.

### CSV에 관한 실무 사항

- **파일 이름**: `프로젝트이름-wbs-2026-09-07.csv` 형식. 이름에서 문자·숫자·`.`·`_`·`-`가
  아닌 것은 `-`로 바뀝니다.
- **한글이 깨지지 않습니다.** 파일 앞에 UTF-8 BOM을 붙여 Windows Excel이 시스템 코드페이지로
  읽는 것을 막습니다.
- **줄바꿈은 CRLF**입니다(RFC 4180, Excel 기본).
- **RACI CSV 맨 끝에는 빈 줄 하나를 두고 범례**가 붙습니다 —
  `RACI: R=RESPONSIBLE, A=ACCOUNTABLE, C=CONSULTED, I=INFORMED`. 받는 사람이 글자의 뜻을
  알 수 있게 하려는 것이고, 표의 열 구조를 흐트러뜨리지 않도록 빈 줄로 떼어 놓습니다.
- **화면의 필터를 따르지 않습니다.** 프로젝트 화면에서 부르므로 그 프로젝트의 데이터를
  **새로 읽어 전부** 내보냅니다. RAID 화면에서 "위험만" 걸러 놓아도 CSV에는 네 종류가 모두
  들어갑니다.
- **불리언 칸은 `Y`/`N`** 으로, 빈 값은 **빈 칸**으로 나갑니다(`null`이라는 글자가 아니라).

### JSON에 관한 실무 사항

- **평범한 링크로 내려받습니다.** 서버가 `Content-Disposition: attachment`로 내려주므로 별도의
  처리가 없고, 개발 프록시와 설치본에서 똑같이 동작합니다. 한글 프로젝트 이름도 그대로 나옵니다.
- **파일 이름**: `프로젝트이름-export-2026-09-07.json`
- **형식 버전(`formatVersion`)은 6**입니다. 파일에 함께 적혀 있습니다.
- **파일 하나에 프로젝트 하나**입니다. 전체를 한 번에 내보내는 기능은 없습니다.

담기는 것: 프로젝트 · 구성원 · WBS 항목(실적·예상 종료일, 가중치, Hybrid α, 인수 상태 포함) ·
선후행 관계 · RACI 배정 · RAID 항목과 연결 · Backlog 항목(차단·완료 시각 포함) ·
Sprint와 배정 이력(종료 결과 포함) · 승인 체크포인트(승인자·승인 시각 포함) ·
승인된 기준선 전부와 그 항목 스냅샷 · 보고 스냅샷.

**담기지 않는 것**: 변경 이력(`change_logs`), Backlog 귀속 변경 이력, 그리고 위에서 말한
모든 판정값.

## 9.2 가져오기가 하는 일과 하지 않는 일

프로젝트 화면 오른쪽 위 **가져오기** 버튼 → 파일 선택. 성공하면 초록 배너에 새 프로젝트 이름이
뜨고, 목록 아래에 새 행이 생깁니다.

### 하는 일

- **항상 새 프로젝트를 만듭니다.** 기존 프로젝트에 병합하려면 "이 항목이 이름만 바뀐 같은
  업무인가"를 행마다 판단해야 하는데, 파일은 그 답을 갖고 있지 않습니다. 공유가 실제로 필요한
  것도 "받은 프로젝트를 내 것 옆에 놓고 보는 것"입니다.
- **이름이 겹치면 뒤에 `(가져옴)`을 붙입니다.** 그것마저 겹치면 `(가져옴 2)`, `(가져옴 3)` …
- **모든 id를 다시 매깁니다.** 파일의 id는 그것을 만든 설치본의 것이라 여기서는 의미가 없습니다.
  상위부터 삽입하며 옛 id → 새 id 맵을 만들고, 선후행·RACI·RAID·Backlog·Sprint의 참조를 그
  맵으로 바꿉니다. **파일 순서에 의존하지 않으므로** 손으로 편집해 순서가 뒤섞인 파일도 들어옵니다.
- **승인 상태를 그대로 가져옵니다.** 체크포인트 승인, 기준선, 종료된 Sprint의 결과, Board의
  차단·완료 시각까지. **승인은 사건이지 현재 데이터의 함수가 아니라서** 다시 계산할 수 없고,
  초기화해서 넘기면 아무것도 이루지 못한 프로젝트를 건네는 셈이 됩니다.
- **구분(`nodeType`)은 파일 값을 믿지 않고 다시 정합니다.** 파일에서 자식이 있으면 파일이
  `WORK_PACKAGE`라고 적어도 `SUMMARY`로 바로잡습니다 — WBS 코드를 다시 계산하는 것과 같은 이유이고,
  하위가 있는 Work Package는 편집 규칙이 허용하지 않는 상태라 받는 쪽에서 고칠 수도 없습니다.
- **Backlog의 귀속은 상위에서 물려받습니다.** 자식 행에 다른 값이 적혀 있어도 무시합니다 —
  이 모델에서 귀속은 언제나 가족의 맨 위에서 오기 때문입니다.
- **구형 파일을 읽습니다.** `formatVersion` 1~5도 들어옵니다. 없는 절은 빈 절과 같게 다루고,
  버전 5 이하의 단일 `wbsItemId`는 `WBS_ITEM` 연결 하나가 됩니다.

### 하지 않는 일

- **기존 프로젝트에 병합하지 않습니다.**
- **파일보다 높은 형식 버전은 거부합니다** —
  `이 버전이 읽을 수 없는 형식입니다 (파일 7, 지원 6). 앱을 업데이트하세요.`
  모르는 필드를 조용히 버리는 것보다 낫다고 보기 때문입니다.
- **계획의 품질은 검증하지 않습니다.** 아래는 경고 없이 그대로 들어옵니다 —
  순환 선후행 관계, 상위·하위 사이의 선후행 관계, 미연결 Backlog, Summary에 귀속된 Backlog,
  종료된 Sprint에서 이후 재오픈된 항목. **사용자 자신의 데이터**이고, 그 문제는 각 화면이
  이미 설명해 줍니다. 거부하면 데이터를 아예 못 넣게 됩니다.
- **부분 가져오기가 없습니다.** "WBS만" 같은 선택지는 없고, CSV는 읽지 못합니다.

### 거부되는 것 — 구조가 성립하지 않을 때

무엇이 문제인지 문장으로 알려 주고 **아무것도 만들지 않습니다.** 검증이 삽입보다 앞에 있어서,
거부된 파일은 빈 프로젝트조차 남기지 않습니다.

| 대상 | 거부 사유 |
|---|---|
| 파일 | 프로젝트 정보 없음, 이름·상태 비어 있음, 형식 버전이 너무 높음, JSON이 아님 |
| WBS | 이름 비어 있음, 상위가 파일에 없음, 자기 자신이 상위, 상위 참조 순환, id 중복 |
| 선후행 | 선행·후행이 파일에 없음, 선행 = 후행, 같은 쌍 중복, 대기 일수 음수 |
| RACI | 업무·구성원이 파일에 없음, 역할 비어 있음, 같은 (업무·구성원·역할) 중복 |
| RAID | 제목 비어 있음, 종류·상태 비어 있음, 소유자가 파일에 없음, 연결 대상이 비었거나 파일에 없음, 같은 연결 중복 |
| Backlog | 제목 비어 있음, 유형·우선순위·상태 비어 있음, 귀속 업무·담당자가 파일에 없음, 자기 자신이 상위, 상위가 파일에 없음, **Task에 상위가 없음**, 허용되지 않는 계층(예: Epic이 Story의 하위) |
| Sprint | 이름 비어 있음·중복, 기간 비어 있음, 종료일이 시작일보다 앞, 상태 비어 있음, **실행 중 Sprint가 둘 이상**, 배정의 Sprint·Backlog가 파일에 없음, 같은 항목이 한 Sprint에 살아 있는 채로 두 번 |

파싱 자체가 실패하면(가장 흔한 실수인 "파일을 잘못 골랐다")
`요청 내용을 읽을 수 없습니다. 형식이 올바른 JSON인지 확인하세요.`가 뜹니다.
값이 enum 범위를 벗어나면 어떤 필드에 무엇이 들어갈 수 있는지까지 알려 줍니다.

## 9.3 주의할 점

### JSON은 백업이 아닙니다

이름이 "전체"라서 오해하기 쉽지만, 이 파일은 **공유 수단이지 백업본이 아닙니다.**

1. **복원이 아니라 복제입니다.** 가져오기는 항상 새 프로젝트를 만듭니다. 실수로 지운 프로젝트를
   **원래 자리로 되돌릴 수는 없습니다** — 옆에 하나 더 만들 수 있을 뿐이고, 다른 화면에서 걸어
   둔 링크나 기억하던 id는 전부 달라집니다.
2. **프로젝트 하나뿐입니다.** 저장소 전체를 한 번에 내보내는 기능이 없어서, 프로젝트가 열 개면
   파일도 열 개를 손으로 받아야 합니다.
3. **생성일·수정일이 보존되지 않습니다.** 가져온 프로젝트의 생성 시각은 **가져온 날**입니다.
4. **변경 이력이 빠집니다.** `change_logs`와 Backlog 귀속 변경 이력은 파일에 담기지 않으므로,
   "언제 누가 왜 바꿨나"는 넘어가지 않습니다.
5. **판정값이 없습니다.** 이것은 의도한 설계지만, 결과적으로 "그날 화면이 어땠는지"는
   복원되지 않습니다.

**진짜 백업은 데이터 폴더를 복사하는 것**입니다. 데스크톱 설치본의 데이터는
`~/.project-flow/data/` 아래 H2 파일에 있습니다. 앱을 종료한 뒤 그 폴더째 복사해 두세요.
서버 프로필로 쓰고 있다면 PostgreSQL 백업이 그 자리를 대신합니다.

### 그 밖에

- **CSV는 가져올 수 없습니다.** Excel에서 고친 표를 되돌려 넣는 경로는 없습니다.
- **CSV 파일 이름의 날짜가 하루 어긋날 수 있습니다** — [발견한 결함](../발견한_결함.md) 참고.
- **내보내기 중 오류가 나면 버튼 옆에 작은 빨간 `!`** 가 붙습니다. 마우스를 올리면 사유가
  뜨고, 누르면 사라집니다.
- **JSON 내보내기는 오류를 화면에 보여 주지 않습니다.** 링크 이동 방식이라 실패하면 브라우저가
  서버 응답(JSON 오류 본문)을 그대로 보여 주게 됩니다.
